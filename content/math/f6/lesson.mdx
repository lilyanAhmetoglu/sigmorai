Floor 4 said training changes the numbers in `W` and `b`. But which way, and by how much? The answer is the gradient: it says which way the error goes up, so training steps the other way. This floor covers slope, the derivative, and gradient descent, with numbers you can check by hand.

## Slope: how fast a line climbs

The slope of a straight line is how much y changes when x goes up by 1. Rise over run.

Example: `y = 3x + 1`. At `x = 2`, `y = 7`. At `x = 3`, `y = 10`. y went up by 3 for one step in x, so the slope is 3.

A positive slope climbs to the right. A negative slope falls to the right. A slope of 0 is flat.

## The derivative: slope at one point

A curve has a different slope at each point. The derivative gives the slope at one point. You can estimate it: move x a tiny bit, and divide the change in y by that tiny step.

Example: a loss `L(θ) = (θ − 3)²`. θ (theta) is one parameter. The loss is lowest, 0, at `θ = 3`.

At `θ = 5`:

- `L(5) = 2² = 4`
- `L(5.01) = 2.01² = 4.0401`
- slope ≈ `(4.0401 − 4) / 0.01 = 4.01`, so about 4

The exact rule for this curve is `L'(θ) = 2(θ − 3)`. At `θ = 5` that gives `2 × 2 = 4`. At `θ = 3` it gives 0: the bottom of the curve is flat.

The sign tells you the way uphill. At `θ = 5` the slope is +4: the loss goes up if θ goes up. So to lower the loss, make θ smaller.

## Gradient descent

Gradient descent repeats one step: move each parameter a little way downhill.

`θ ← θ − η∇L`: update the parameters theta: subtract the learning rate eta times the gradient of the loss L.

η (eta) is the learning rate, a number you choose. It sets the size of each step, and the right size depends on the problem. With one parameter, `∇L` is just the derivative.

Worked example: `L(θ) = (θ − 3)²`, start at `θ = 5`, learning rate `η = 0.1`.

| Step | θ     | Loss   | Slope `2(θ − 3)` | New θ                  |
| ---- | ----- | ------ | ---------------- | ---------------------- |
| 1    | 5     | 4      | 4                | `5 − 0.1 × 4 = 4.6`    |
| 2    | 4.6   | 2.56   | 3.2              | `4.6 − 0.32 = 4.28`    |
| 3    | 4.28  | 1.6384 | 2.56             | `4.28 − 0.256 = 4.024` |
| 4    | 4.024 | 1.0486 |                  |                        |

The loss falls every step: 4, 2.56, 1.64, 1.05. Here each step keeps 80% of the distance to 3 (2, then 1.6, then 1.28, then 1.024), so θ keeps getting closer.

## Too big a step

The learning rate sets the step size. Try `η = 1.1` from `θ = 5`:

- step 1: `θ = 5 − 1.1 × 4 = 0.6`, loss `(0.6 − 3)² = 5.76`
- step 2: slope `2 × (−2.4) = −4.8`, `θ = 0.6 + 5.28 = 5.88`, loss `2.88² = 8.2944`

The loss went 4, 5.76, 8.29: up, not down. Each step jumps over the bottom and lands further away. Too small a learning rate has the opposite problem: every step is safe but tiny, so training is slow.

## Many parameters: the gradient

A real model has many parameters. The gradient is the list of slopes, one per parameter: how the loss changes if you nudge that one parameter alone.

Example: `L(a, b) = a² + 3b²`. The slope for a is `2a`, and the slope for b is `6b`. So `∇L = (2a, 6b)`.

At `(a, b) = (1, 1)`: loss `1 + 3 = 4`, gradient `(2, 6)`. With `η = 0.1`:

- `a = 1 − 0.1 × 2 = 0.8`
- `b = 1 − 0.1 × 6 = 0.4`
- new loss: `0.8² + 3 × 0.4² = 0.64 + 0.48 = 1.12`

One step took the loss from 4 to 1.12. b moved more than a, because the loss is steeper in the b direction.

## Gradient descent in real code

The OpenAI cookbook's embedding example (the learned matrix from floor 4) trains with this exact step. Its update line is:

`matrix -= matrix.grad * learning_rate`

That is `θ ← θ − η∇L`, with the whole matrix as θ. Its training function is described as returning a "matrix optimized to minimize loss on training data", and its default is `max_epochs = 100` passes over the data (the notebook's own runs use 30).

You also meet these words when you fine-tune a hosted model. The Claude glossary defines fine-tuning as "further training a pretrained language model using additional data"; it also says the Claude API does not currently offer it. OpenAI's fine-tuning guide lists the knobs:

- **Epochs:** "An epoch is a single complete pass through your entire training dataset during model training."
- **Learning rate multiplier:** "Adjusts the size of changes made to the model's learned parameters." OpenAI says a larger one can speed up training, and a smaller one tends toward slower but more stable training. That is the step-size trade-off above.
- **Batch size:** "The number of examples the model processes in one forward and backward pass before updating its weights."

For an open-weight model, OpenAI's cookbook fine-tunes `gpt-oss-20b` with `learning_rate = 2e-4`, which is 0.0002: a very small step.

## Key points

- Slope: how much y changes per step in x. The derivative is the slope at one point.
- The sign of the derivative says which way is uphill. Training steps the other way.
- Gradient descent: `θ ← θ − η∇L`. With `L = (θ − 3)²`, `θ = 5`, `η = 0.1`, one step gives `θ = 4.6`.
- Too large a learning rate overshoots and the loss grows. Too small is slow.
- The gradient is one slope per parameter. Fine-tuning settings like epochs and the learning rate multiplier control this same loop.
