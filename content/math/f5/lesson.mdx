Floor 2 showed the model's output as a table of probabilities. The model does not make those probabilities directly. It makes raw scores, and one formula, softmax, turns the scores into probabilities. Temperature is one number inside that formula. This floor shows the formula and works it by hand.

## Logits: raw scores

In the math of a language model, the last step gives one raw score per token in its vocabulary. These scores are called logits. A logit can be any number: positive, negative or zero. A bigger logit means the model favours that token more.

Logits are not probabilities. They don't sit between 0 and 1, and they don't add up to 1. Here is a made-up example for the text `The sky is`:

| Token    | Logit |
| -------- | ----- |
| ` blue`  | 2     |
| ` clear` | 1     |
| ` dark`  | 0     |

## Softmax turns scores into probabilities

Softmax does two things. First it makes every score positive with `e^z`. Then it divides by the total, so the results add up to 1.

`p_i = e^(z_i) / Σ e^(z_j)`: the probability of token i is e to the power of its logit z-i, divided by the sum of e to the power of every logit z-j.

`e ≈ 2.718` is the same e as in floor 2, where `e^x` undid `ln`. `e^z` is always positive, and a bigger z gives a bigger `e^z`.

Worked example with the logits above:

| Token    | Logit z | e^z     | Probability              |
| -------- | ------- | ------- | ------------------------ |
| ` blue`  | 2       | `7.389` | `7.389 / 11.107 ≈ 0.665` |
| ` clear` | 1       | `2.718` | `2.718 / 11.107 ≈ 0.245` |
| ` dark`  | 0       | `1`     | `1 / 11.107 ≈ 0.090`     |

The total is `7.389 + 2.718 + 1 = 11.107`. Check: `0.665 + 0.245 + 0.090 = 1.000`.

Three things to notice:

- The order stays the same. The biggest logit gets the biggest probability.
- A gap of 1 in the logits means a ratio of `e` in the probabilities: ` blue` is `7.389 / 2.718 ≈ 2.718` times as likely as ` clear`.
- Adding the same number to every logit changes nothing. Logits `(5, 4, 3)` give the same `0.665, 0.245, 0.090`. Only the gaps count.

## Temperature divides the logits

In the textbook formula, temperature `T` divides every logit before softmax:

`p_i = e^(z_i/T) / Σ e^(z_j/T)`: the same formula, with each logit divided by the temperature T first.

Dividing by T changes the gaps. A small T makes the gaps bigger. A big T makes them smaller. Same logits `(2, 1, 0)`:

| T   | Logits ÷ T    | ` blue` | ` clear` | ` dark` |
| --- | ------------- | ------- | -------- | ------- |
| 0.5 | `(4, 2, 0)`   | 0.867   | 0.117    | 0.016   |
| 1   | `(2, 1, 0)`   | 0.665   | 0.245    | 0.090   |
| 2   | `(1, 0.5, 0)` | 0.507   | 0.307    | 0.186   |

Check T = 0.5: `e^4 ≈ 54.598`, `e^2 ≈ 7.389`, `e^0 = 1`, total `62.987`. So ` blue` gets `54.598 / 62.987 ≈ 0.867`.

Check T = 2: `e^1 ≈ 2.718`, `e^0.5 ≈ 1.649`, `e^0 = 1`, total `5.367`. So ` blue` gets `2.718 / 5.367 ≈ 0.507`.

The two ends, as math:

- **T close to 0:** the gaps grow without limit, so the top token gets almost all the probability. That is greedy decoding from floor 2. (T = 0 itself would divide by zero. The Gemini docs below describe temperature 0 as always picking the most probable response.)
- **T very large:** the gaps shrink toward 0, so every token gets almost the same share.
- **T = 1:** the logits are used as they are.

## Temperature in the APIs

The cited docs don't give the exact sampling code. What they describe matches the formula: lower temperature is more focused, higher is more random.

- **OpenAI:** temperature is "What sampling temperature to use, between 0 and 2. Higher values like 0.8 will make the output more random, while lower values like 0.2 will make it more focused and deterministic." OpenAI also writes: "We generally recommend altering this or top_p but not both."
- **Claude:** the Messages API says temperature "Defaults to `1.0`. Ranges from `0.0` to `1.0`." Use it "closer to `0.0` for analytical / multiple choice, and closer to `1.0` for creative and generative tasks." The field is now marked deprecated: "Models released after Claude Opus 4.6 do not support setting temperature." For those models, only 1.0 is accepted; other values get a 400 error.
- **Gemini:** "A temperature of 0 is deterministic, meaning that the highest probability response is always selected." For Gemini 3.x models, Google strongly recommends keeping temperature at its default, because a change (for example "setting the temperature below 1.0") "can cause unexpected behavior, such as looping or degraded performance".

The Claude glossary adds the warning from floor 2: "Even with temperature set to 0, the results will not be fully deterministic." The formula explains the pick; the served API can still vary for other reasons.

Note the ranges differ: 0 to 2 for OpenAI, 0 to 1 for Claude. The same number does not mean the same thing on every API. Read the docs for the model you call.

## Key points

- Logits are raw scores, one per token. They can be any number.
- Softmax: `e^z` for each logit, divided by the total. The results are positive and add up to 1.
- Logits `(2, 1, 0)` give `0.665, 0.245, 0.090`. Only the gaps between logits count.
- Temperature divides the logits first. Low T sharpens the table, high T flattens it.
- APIs differ in range and support. Some newer models don't let you change temperature at all.
