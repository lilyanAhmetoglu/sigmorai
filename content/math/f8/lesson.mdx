The top floor builds on three earlier floors. Attention is how a token in a transformer looks at the other tokens and decides which ones matter. It uses the dot product (floor 1), matrices (floor 4) and softmax (floor 5). This floor works one attention step by hand.

## Where attention comes from

In 2017, a paper by researchers mostly at Google, "Attention Is All You Need", proposed "a new simple network architecture, the Transformer, based solely on attention mechanisms". Anthropic's engineering team writes that "LLMs are based on the transformer architecture, which enables every token to attend to every other token across the entire context."

Open-weight models have attention too. OpenAI's cookbook guide to fine-tuning the open-weight `gpt-oss-20b` model targets "the attention layers" of the model.

## Queries, keys and values

Each token starts as a vector. In the math of attention, three new vectors are made from it, each with its own learned matrix (floor 4):

- **Query (q):** what this token is looking for.
- **Key (k):** what this token offers, so others can find it.
- **Value (v):** what this token passes on if it is chosen.

A comparison: a library search. Your query is the question. Each book's key is its label. The value is what is inside the book. You compare your question with every label, then read the best matches most.

## One attention step

For one token's query `q`, the step is:

1. **Score:** take the dot product of q with every key. A bigger score means a better match.
2. **Scale:** divide every score by `√d`, where d is the number of values in each key.
3. **Weights:** apply softmax to the scaled scores, so they are positive and add up to 1.
4. **Mix:** add up the value vectors, each times its weight.

The result is a new vector for this token: a blend of the other tokens, weighted by how well they matched.

## Worked example

Three tokens. Keys have `d = 4` numbers, so `√d = 2`. The query is `q = (1, 0, 1, 0)`.

| Token | Key k          | `q·k`       | `÷ 2` | Weight | Value v  |
| ----- | -------------- | ----------- | ----- | ------ | -------- |
| 1     | `(1, 0, 1, 0)` | `1 + 1 = 2` | 1     | 0.506  | `(1, 0)` |
| 2     | `(0, 1, 0, 1)` | `0`         | 0     | 0.186  | `(0, 1)` |
| 3     | `(1, 1, 0, 0)` | `1`         | 0.5   | 0.307  | `(1, 1)` |

The weights are softmax of `(1, 0, 0.5)`: `e^1 ≈ 2.718`, `e^0 = 1`, `e^0.5 ≈ 1.649`, total `5.367`. So `2.718 / 5.367 ≈ 0.506`, `1 / 5.367 ≈ 0.186`, and `1.649 / 5.367 ≈ 0.307`. The weights add up to 1 (the rounded numbers show 0.999).

Now mix the values:

- first number: `0.506 × 1 + 0.186 × 0 + 0.307 × 1 ≈ 0.814`
- second number: `0.506 × 0 + 0.186 × 1 + 0.307 × 1 ≈ 0.494`
- output: `(0.814, 0.494)`

(With the rounded weights you get 0.813 and 0.493; the small gap is rounding.)

Token 1's key matched the query best, so its value counts most. Token 2 did not match at all (score 0), but softmax still gives it a small share.

## Why divide by √d

Compare floor 5. Dividing the scores by `√d = 2` is the same as softmax with temperature 2. Without it, the scores `(2, 0, 1)` give weights `0.665, 0.090, 0.245`: sharper.

As math: a dot product adds up d products, so with longer keys the scores tend to get bigger. Bigger gaps make softmax sharper, until one token takes almost all the weight. Dividing by `√d` keeps the gaps in a range where several tokens can still share the weight.

## All tokens at once

Each token has its own query, so you repeat the step for every token. With matrices this is one formula. Put every query in a row of Q, every key in a row of K, and every value in a row of V:

`softmax(QKᵀ/√d)V`: multiply the queries Q by the keys K transposed, divide by the square root of the key size d, apply softmax, then multiply by the values V.

`QKᵀ` is floor 4's trick: one matrix multiply gives every query · key score. For n tokens, that is an n × n grid of scores. Softmax runs on each row, and the multiply by V does the mixing for every token at once.

## Why long context is hard

That n × n grid is why context length costs so much. Anthropic: every token attending to every other token "results in n² pairwise relationships for n tokens."

- 1,000 tokens: `1,000² = 1,000,000` pairs.
- 10,000 tokens: `100,000,000` pairs. Ten times the text, a hundred times the pairs.

Anthropic adds: "As its context length increases, a model's ability to capture these pairwise relationships gets stretched thin". It calls this the model's "attention budget", and says every new token "depletes this budget by some amount". Its advice is to find "the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome." Put the tokens that matter in the context, and leave out the rest.

## Key points

- Attention lets each token build a new vector from the other tokens, weighted by how well they match.
- Each token has a query, a key and a value, made with learned matrices.
- One step: dot product q with every key, divide by `√d`, softmax, then a weighted sum of the values.
- Dividing by `√d` works like a temperature: it stops softmax from getting too sharp.
- `softmax(QKᵀ/√d)V` does it for all tokens at once. The n × n score grid is why long context is costly.
