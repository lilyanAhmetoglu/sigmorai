## Goal

After this lesson you can:

- Name the query, key and value of a token, and say what each one is for.
- Work one attention step by hand: score, scale by `√d`, softmax, mix.
- Read `softmax(QKᵀ/√d)V`, and say why long context costs so much.

## The problem

You read that a model pays attention to parts of its context (the text the model has in front of it), and that long context gets expensive and less focused. Both facts come from one small piece of math, repeated for every token.

Attention is how a token in a transformer looks at the other tokens and decides which ones matter for it. It uses three tools: the dot product, matrices and softmax. This lesson puts them together and works one attention step by hand.

## The idea

### Where attention comes from

In 2017, the paper "Attention Is All You Need" ([Google Research](https://research.google/pubs/attention-is-all-you-need/), [arXiv](https://arxiv.org/abs/1706.03762)) proposed "a new simple network architecture, the Transformer, based solely on attention mechanisms". The [Anthropic engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) says: "LLMs are based on the transformer architecture, which enables every token to attend to every other token across the entire context."

Open-weight models (models whose weights you can download) have attention too. The [OpenAI cookbook](https://developers.openai.com/cookbook/articles/gpt-oss/fine-tune-transfomers) on fine-tuning `gpt-oss-20b` mentions "targeting the attention layers" of that model.

### Queries, keys and values

Each token starts as a vector (a list of numbers). Attention makes three new vectors from it. Each one comes from its own learned matrix:

- **Query (q):** what this token is looking for.
- **Key (k):** what this token offers, so others can find it.
- **Value (v):** what this token passes on if it is chosen.

A small comparison: a library. Your query is your question. Each book's key is its label. Its value is what is inside. You compare your question with every label, then read the best matches most.

### One attention step

For one token's query `q`:

1. **Score:** the dot product of q with every key: multiply the numbers at each position, then add. A bigger score means a better match.
2. **Scale:** divide every score by `√d` (the square root of d). d is how many numbers each key has. Our example: scores 6 and 3 with `d = 9`. `√9 = 3`, so they become `6 / 3 = 2` and `3 / 3 = 1`.
3. **Weights:** apply softmax to the scaled scores. Softmax takes `e^s` of each score s (`e ≈ 2.718`, where `≈` means "about", and `e^s` is e to the power s), then divides by the total. The weights are positive and add up to 1.
4. **Mix:** multiply each value vector by its weight, then add the results. Our example: weights 0.75 and 0.25, values `(4, 0)` and `(0, 8)`. The mix is `0.75 × (4, 0) + 0.25 × (0, 8) = (3, 0) + (0, 2) = (3, 2)`.

The result is a new vector for this token: a blend of the values, weighted by how well each key matched.

### Why divide by √d

Dividing every score by the same number works like a temperature in softmax. Bigger gaps between scores make softmax sharper, until one token takes almost all the weight. A dot product adds up d products, so with longer keys the scores tend to get bigger. Dividing by `√d` keeps the gaps in a range where several tokens can still share the weight. The order is always: score, scale, then softmax. The paper says: "for large values of dk, the dot products grow large in magnitude". (There, dk is the key size, our d.)

### All tokens at once

Each token has its own query, so the step repeats for every token. With matrices, it is one formula. Put every query in a row of `Q`, every key in a row of `K`, and every value in a row of `V`:

`softmax(QKᵀ/√d)V`: multiply the queries Q by the keys K transposed, divide by the square root of the key size d, apply softmax, then multiply by the values V.

`Kᵀ` is K **transposed**: rows become columns. So `QKᵀ` is one matrix multiply that gives every query · key score. For n tokens, that is an n × n grid. Softmax runs on each row on its own. The multiply by `V` does the mixing for every token at once.

### Why long context is hard

That n × n grid is why long context costs so much. The Anthropic engineering post says attention "results in n² pairwise relationships for n tokens." (`n²` means n × n.)

- 1,000 tokens: `1,000² = 1,000,000` pairs.
- 3,000 tokens: `3,000² = 9,000,000` pairs. Three times the tokens, nine times the pairs.

The post adds three points:

- "As its context length increases, a model's ability to capture these pairwise relationships gets stretched thin".
- LLMs have an "attention budget", and "Every new token introduced depletes this budget by some amount".
- Good context engineering means "finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome."

## Worked example

Our example: three tokens. Each key has `d = 4` numbers, so `√d = 2`. We compute the new vector for one token, with query `q = (1, 0, 1, 0)`.

```text
token   key k          value v
1       (1, 0, 1, 0)   (1, 0)
2       (0, 1, 0, 1)   (0, 1)
3       (1, 1, 0, 0)   (1, 1)
```

The questions: which token's value counts most, and does token 2 still count?

### Step 1: score

- token 1: `1×1 + 0×0 + 1×1 + 0×0 = 2`
- token 2: `1×0 + 0×1 + 1×0 + 0×1 = 0`
- token 3: `1×1 + 0×1 + 1×0 + 0×0 = 1`

### Step 2: scale

Divide by `√4 = 2`: the scores `(2, 0, 1)` become `(1, 0, 0.5)`.

### Step 3: softmax

- `e^1 ≈ 2.718`, `e^0 = 1`, `e^0.5 ≈ 1.649`
- total: `2.718 + 1 + 1.649 = 5.367`
- weights: `2.718 / 5.367 ≈ 0.506`, `1 / 5.367 ≈ 0.186`, `1.649 / 5.367 ≈ 0.307`

The rounded weights add up to 0.999. The exact ones add up to 1.

### Step 4: mix

- first number: `0.506 × 1 + 0.186 × 0 + 0.307 × 1 ≈ 0.814`
- second number: `0.506 × 0 + 0.186 × 1 + 0.307 × 1 ≈ 0.494`
- output: `(0.814, 0.494)`

(With the rounded weights you get 0.813 and 0.493. The small gap is rounding.)

Token 1 matched best, so its value counts most. Token 2 had a score of 0, but softmax still gives it 0.186 of the weight. So yes, token 2 still counts.

### Step 5: the hard case, skip the scale

**This is the hard case.** What if Step 2 is left out? Softmax of `(2, 0, 1)` gives about `0.665, 0.090, 0.245`. The output becomes about `(0.910, 0.335)`.

Before (no scale): token 1 takes 0.665 and token 2 drops to 0.090. After (with scale): 0.506 and 0.186. Here `d` is only 4, so the change is small. With real key sizes, `√d` is much bigger, and leaving it out can let one token take almost all the weight.

### Step 6: why it is better

- **Softer weights.** With the scale, the weights stay spread out (0.506, 0.186, 0.307).
- **Same math for every token.** Each query runs these four steps, and the matrix form runs them all at once.
- **Easy to check.** Each row of weights adds up to 1.

## Common mistakes

1. **Scoring the query against the values.** Values are not compared with anything. Fix: score with the keys, and use the values only in the mix.
2. **Using the value size as d.** In our example the values have 2 numbers, but the keys have 4. Fix: d is the number of numbers in each key.
3. **Running softmax over the whole n × n grid at once.** Then the weights for one token don't add up to 1. Fix: softmax runs on each row, one query at a time.

## Try it

Not graded. Write your answer down before you read the answer.

Our example: same query and same three tokens as the worked example. A fourth token joins. Its key is a copy of token 1's key, `(1, 0, 1, 0)`.

1. What are the four scaled scores?
2. What are the four weights?
3. Does token 1 alone get more or less weight than before? What do token 1 and its copy get together?

### Answer

1. Token 4 scores `2`, like token 1, and `2 / 2 = 1`. The scaled scores are `(1, 0, 0.5, 1)`.
2. `e^1 ≈ 2.718`, `e^0 = 1`, `e^0.5 ≈ 1.649`, `e^1 ≈ 2.718`. The total is `8.085`. Weights: `2.718 / 8.085 ≈ 0.336`, `1 / 8.085 ≈ 0.124`, `1.649 / 8.085 ≈ 0.204`, and `0.336` again.
3. Less: token 1 drops from 0.506 to 0.336. The weights must still add up to 1, so a new token takes a share from the others. Together, the two copies get `0.336 + 0.336 = 0.672`, more than token 1 had alone.

## Recap

- Each token has a query, a key and a value, made with learned matrices. Its new vector is a blend of the values, weighted by how well its query matches each key.
- One step: dot product with every key, divide by `√d`, softmax, then mix the values. Dividing by `√d` stops softmax from getting too sharp.
- `softmax(QKᵀ/√d)V` does it for all tokens at once. The n × n score grid is why long context is costly.
