## Goal

After this lesson you can:

- Name the three parts of an MCP link (host, client, server) and say where a server runs.
- Check, for each AI vendor's API, whether it can reach a given server as it is.
- Pick a safe route for a server that must stay private, and spot the parts that are beta or preview.

## The problem

A wedding-film studio is building its own small AI app. The app calls three model APIs: Claude, OpenAI (the Responses API) and Gemini. The team wants the app to use three tools:

1. **Music search.** A music-licence company hosts a search server for its customers. It has a public HTTPS address. The team copied the address from an old blog post. It ends in `/sse`.
2. **Colour presets.** The lead editor wrote a small server that reads the studio's colour presets. It runs on the editing PC in the back room.
3. **Contracts.** A server that reads signed client contracts. It sits on the office network. The owner says: "This one never goes on the internet."

The plan says: "MCP is one standard, so all three tools work with all three APIs." That sentence is not true. This lesson shows how to check each line.

## The idea

### What MCP is

**MCP** (Model Context Protocol) is a shared set of rules for linking an AI app to other systems. The [MCP docs](https://modelcontextprotocol.io/docs/getting-started/intro) say: "MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems." They give a picture: "Think of MCP like a USB-C port for AI applications."

The [MCP architecture page](https://modelcontextprotocol.io/docs/learn/architecture) names three parts:

- **Host**: the AI app the person uses, such as Claude Code or Visual Studio Code.
- **Client**: a small part inside the host that talks to one server. The host makes "one MCP client for each MCP server". Every client has a separate line to its server. So a host linked to three servers has three clients.
- **Server**: a program that gives context or tools to the client.

```text
HOST (the AI app)
  client 1  ----  server A  (music search)
  client 2  ----  server B  (colour presets)
  client 3  ----  server C  (contracts)
```

### Where a server runs

A **transport** is the way messages travel between client and server. The architecture page names two:

- **STDIO**: for a server on the same machine as the host. These servers "typically serve a single MCP client". People call them local servers.
- **Streamable HTTP**: for a server on a network. These "will typically serve many MCP clients". People call them remote servers.

The page also says a server is a server "regardless of where it runs". Local or remote is about the place, not the kind of program.

### What each vendor's API can reach

When your own app calls a model API, the vendor's API talks to the server for you. So each vendor sets its own rules. Here are the live rules from each page.

**Claude, MCP connector (beta).** The [Claude docs](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector) list these limits:

- "The server must be publicly exposed through HTTP (supports both Streamable HTTP and SSE transports)."
- "Local STDIO servers cannot be connected directly."
- From the MCP feature set, "only tool calls are currently supported".
- The server `url` "Must start with https://".

**OpenAI, MCP tool.** The [OpenAI docs](https://developers.openai.com/api/docs/guides/tools-connectors-mcp) say remote servers "can be any server on the public Internet". The Responses API "works with remote MCP servers that support either the Streamable HTTP or the HTTP/SSE transport protocols."

**Gemini, Remote MCP.** The [Gemini API docs](https://ai.google.dev/gemini-api/docs/function-calling) describe Remote MCP in the Interactions API with two limits:

- "Remote MCP only works with Streamable HTTP servers. SSE (Server-Sent Events) servers are not supported."
- "MCP server names should not include the `-` character. Use `snake_case` server names instead."

Our summary table, built from those pages:

| Server                  | Claude connector (beta) | OpenAI MCP tool | Gemini Remote MCP |
| ----------------------- | ----------------------- | --------------- | ----------------- |
| Public, Streamable HTTP | Yes                     | Yes             | Yes               |
| Public, SSE only        | Yes                     | Yes             | No                |
| Private network         | MCP tunnel (preview)    | Secure tunnel   | Not on this page  |
| Local STDIO             | Not directly            | Secure tunnel   | Not on this page  |

"Not on this page" means the Gemini page we cite is silent on it. It does not mean "impossible".

### Private servers: tunnels

Some servers must never be reachable from the public internet. Both Claude and OpenAI offer a tunnel. A tunnel here is a link that starts **inside** your network and goes **out** to the vendor. You do not open a door from the outside.

- The [OpenAI tunnel docs](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) say: "An MCP tunnel is an outbound-only connection from a host inside your network to an OpenAI-hosted MCP endpoint." The page lists "a developer machine" as one place the server can run, and the tunnel program can reach a server "over stdio or HTTP".
- The [Claude tunnel docs](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview) say traffic "flows over an outbound-only connection, so you don't need to open inbound firewall ports". The page also says: "MCP tunnels are in research preview." They are "as-is", and "Anthropic may modify or discontinue MCP tunnels at any time." To set one up, you need "a Kubernetes cluster, or a VM with Docker and Docker Compose".

### What it costs

The OpenAI docs say: "you only pay for tokens used when importing tool definitions or making tool calls. No additional fees apply per tool call." So there is no fee per call. But a server with a long tool list adds tokens before any tool runs.

## Worked example

### Step 1: the weak plan

```text
Music search    public HTTPS, address ends in /sse  -> Claude, OpenAI, Gemini
Colour presets  editing PC, STDIO                   -> Claude, OpenAI, Gemini
Contracts       office network, private             -> Claude, OpenAI, Gemini
```

### Step 2: check each line against the pages

```text
Music search    Claude  OK  (public HTTPS; SSE is accepted)
                OpenAI  OK  (HTTP/SSE is accepted)
                Gemini  NO  (SSE servers are not supported)
Colour presets  Claude  NO  (local STDIO cannot be connected directly)
                OpenAI  only through Secure MCP Tunnel
                Gemini  not described on the cited page
Contracts       Claude  only through an MCP tunnel (research preview)
                OpenAI  only through Secure MCP Tunnel
                Gemini  not described on the cited page
```

### Step 3: the hard case

**The hard case is the music server.** It looks like the easy one: public, HTTPS, run by the company itself. It passes two of three checks. It fails on Gemini only because of the old `/sse` address.

The fix is not to change vendors. Ask the music company if it offers a Streamable HTTP address. If it does, use that address for all three APIs. Then one line in your sheet works everywhere.

### Step 4: the good plan

```text
Music search    Streamable HTTP address from the vendor -> all three APIs
                (Gemini name: music_search, no dash)
Colour presets  not needed by the API. The editor uses it in a desktop
                host on the editing PC. If the app needs it later,
                use OpenAI's tunnel, or move it to a server first.
Contracts       private. OpenAI: Secure MCP Tunnel.
                Claude: MCP tunnel, marked "research preview" in our sheet.
                Gemini: no link until a page describes a private route.
```

### Step 5: why it is better

- **Each line names a route the page supports.** Nothing depends on "MCP is one standard".
- **The private server stays private.** Both tunnels go outbound, so no firewall door is opened.
- **Preview parts are written down.** If Anthropic changes the tunnel, the team knows which line to fix.
- **One transport for the public server.** Streamable HTTP is the one all three pages accept.

## Common mistakes

1. **"It speaks MCP, so every API can reach it."** The standard is shared, but every API sets its own rules. Fix: check transport, place and features for each vendor.
2. **Hiding a private server behind a long, odd address.** A hidden address is still a public address. Fix: use an outbound-only tunnel.
3. **Building on a preview as if it were stable.** A research preview can change or end. Fix: mark every beta and preview in your connection sheet.

## Try it

Not graded. Write your answer down before you read the answer.

A teammate writes three notes. Which are right?

```text
a) Our host app links to 4 servers, so it runs 1 client for all of them.
b) Our script server runs on one laptop over STDIO. It will probably
   serve many clients at once.
c) For the Claude connector we use http://scripts.example.org/mcp,
   a public address.
```

### Answer

1. **a) Wrong.** Four servers means four clients. The host makes a separate client, with a separate line, for every server.
2. **b) Wrong.** The MCP architecture page says local STDIO servers typically serve a single client. Remote Streamable HTTP servers typically serve many.
3. **c) Wrong.** The Claude docs say the server `url` must start with `https://`. Ask for an HTTPS address.

## Recap

- MCP links a host (the AI app) to servers. The host runs one client per server. Local servers use STDIO; remote servers use Streamable HTTP.
- Each vendor API reaches a different set of servers. Claude's connector takes public HTTP servers (Streamable HTTP or SSE) and only tool calls. OpenAI takes Streamable HTTP or HTTP/SSE. Gemini takes Streamable HTTP only.
- Private servers use an outbound-only tunnel (OpenAI's Secure MCP Tunnel, or Claude's MCP tunnels in research preview). OpenAI charges no fee per call, only the tokens that tool lists and calls use.
