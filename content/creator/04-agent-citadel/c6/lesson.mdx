## Why it matters

The first five chapters showed what an agent can do and how to keep it in check. This chapter is about what it cannot do, and where it can hurt you. A studio that knows these limits can say "yes, with conditions" instead of "yes" or "no".

## Errors add up

Anthropic warns about "the potential for compounding errors" in agents. Here is what that means with made-up numbers. This example is ours, not a vendor figure.

Say a chain has 5 steps: brief, storyboard, clips, review, post. Say each step is right 90 times out of 100. The chance that all five are right is 0.9 × 0.9 × 0.9 × 0.9 × 0.9, which is about 0.59. That is 59 times out of 100. Each step looks good. The chain as a whole fails four times in ten.

This is why the earlier chapters add checks between steps, and a person at the end. A check does not remove the error. It catches it before the next step builds on it.

## Give the agent a way to see the real result

Anthropic says it is "crucial for the agents to gain 'ground truth' from the environment at each step (such as tool call results or code execution) to assess its progress". An agent that cannot see what happened is guessing. For a creative chain, "ground truth" means things like: the file exists, the length is right, the check script says pass. It does not mean the agent says it is fine.

## More agents is not better

A slide that shows six specialist agents (concept, storyboard, image, video, voice, review) looks impressive. OpenAI's orchestration guide says the opposite. "Start with one agent whenever you can." Add specialists only when they "materially improve capability isolation, policy isolation, prompt clarity, or trace legibility". And: "Splitting too early creates more prompts, more traces, and more approval surfaces without necessarily making the workflow better."

A good reason for a second agent: the posting tool needs its own strict rules, so it lives apart from the drawing tools (policy isolation). A weak reason: every step "should" have its own agent.

## What the agent can reach

An agent acts with the access you give it. Google's agents page says about managed agents: "The agent may use any credential it has access to, so only provide credentials whose full scope you are willing to grant." It advises least-privilege accounts and short-lived tokens. It also says the sandbox has unrestricted outbound network access by default, and that you can restrict it with an allowlist.

Example: if the agent gets the brand's admin login, a mistake could change the whole account. If it gets a key that can only upload drafts, the worst mistake is a bad draft.

Anthropic recommends "extensive testing in sandboxed environments, along with the appropriate guardrails". For a studio: run the first jobs on a dummy brand, with a test account and the posting tool turned off.

## Preview and beta features change

Several tools in this realm are labelled as unfinished:

- Google lists managed agents as a **Public Preview**.
- Claude's outcomes and permission policies are **beta**.
- Anthropic's own agents post says that much of the tooling it describes "has changed since December 2024".

So treat names, settings and limits as things to re-check before every client job. Do not promise a client a behaviour that the vendor has not made stable.

## Places where work can disappear

Google's page lists limits for managed agents: "Environments are permanently deleted after 7 days of inactivity." If an agent waits ten days for a client reply, its workspace may be gone.

So keep your own copy of the things that matter: the brief, the storyboard, the rubric, the approved files and the review results. They belong in the studio's own folder, not only inside the agent's environment.

Claude's outcomes page has a smaller limit worth knowing: "Only one outcome is supported at a time", though outcomes can be chained in sequence. A plan that needs two goals at once must be changed.

## What an agent does not know

An agent does not know your client's taste. It does not know that the founder hates a certain shade of green, or that a competitor ran a similar ad last week. This list is ours. It is why a person signs (Chapter 5).

## What this means for your work

- **Add checks between steps.** Errors multiply along a chain.
- **Give the agent real results to look at.** A file check beats a promise.
- **Start with one agent.** Split only for a clear reason, such as a strict posting rule.
- **Give the smallest access that works.** A draft-only key, not an admin login.
- **Test on a dummy brand first.**
- **Re-check preview and beta features before each job.**
- **Keep your own copy of the brief, plan, rubric and files.**
