## Goal

After this lesson you can:

- Choose how to get a new shape from one approved master: crop, outpaint or regenerate.
- Plan a reframe, an upscale and an HDR file inside each vendor's rules.
- Pick the right file format for each person who gets the clip.

## The problem

A city museum approved a 10-second 16:9 master: soft light slowly reveals an old painting on a gallery wall. The painting sits on the left third of the frame. The clip was made on Luma.

Now the museum needs a square version for its feed, a file for a colourist (the person who adjusts the colours), and a file for its social team. Each new file must stay true to the master. A new take would change the motion the museum approved.

## The idea

### Three ways to a new shape

This grouping is ours:

| Way        | What happens                               | Risk                   |
| ---------- | ------------------------------------------ | ---------------------- |
| Crop       | cut the master down to the new shape       | the edges are lost     |
| Outpaint   | keep the master, add new picture around it | the new area can drift |
| Regenerate | make a new take in the new shape           | everything is new      |

**Outpaint** means the model adds new picture beyond the old edges.

- The [Luma reframing docs](https://docs.agents.lumalabs.ai/guides/videos/reframing) say `video_reframe` "outpaints an existing video to a new target aspect ratio. The source video content is preserved frame-for-frame". Use it "when you want the same clip in a different shape". Use `video_edit` to restyle.
- On Runway, Aleph 2.0 has `targetAspectRatio`, a "Target aspect ratio for expand/outpaint" ([API reference](https://docs.dev.runwayml.com/api)).

**Regenerate.** On Veo and Gemini Omni Flash, the shape is a setting of a new clip, 16:9 or 9:16. The [Gemini API docs](https://ai.google.dev/gemini-api/docs/omni) say: "Set the aspect_ratio to "9:16" to create portrait videos." A new take has new motion, so it needs a new approval (our advice).

Our advice: outpaint when the client approved the master's motion. Regenerate when the new shape needs a new layout.

### Luma reframe rules (October 2026)

- **Ratios.** "Use one of the six Ray 3.2 video ratios": 9:16, 3:4, 1:1, 4:3, 16:9 and 21:9.
- **Length.** "Reframe cannot produce output longer than 10s, and the source video is capped at the same 10s ceiling." For a longer clip: "split it into ≤10s segments and reframe each one". Output "Defaults to 5s".
- **Resolution.** "1080p works for landscape and square aspect ratios". Vertical 9:16 and 3:4 at 1080p "return a "coming soon" 400", so use 720p or lower for those.
- **Prompt.** It says "how the new canvas area should be filled".
- **No HDR.** HDR is "Rejected — reframe is standard dynamic range only". (HDR, high dynamic range, stores a wider range of bright and dark.)

### Where the source sits

By default, Luma "fits the source video into the new canvas with a centered crop and outpaints the exposed area". To choose the place yourself, pass `video.source_position`, "a normalized rectangle measured as fractions of the output canvas". It has four fields: `x_norm` and `y_norm` (the top-left corner) and `w_norm` and `h_norm` (the size). "All four fields are required when source_position is present."

A small comparison: the canvas is a new, bigger frame, and `source_position` says where you hang the old picture inside it.

### Upscale: bigger, not newer

To **upscale** is to make a clip bigger in pixels. On Runway, the [Professional outputs page](https://docs.dev.runwayml.com/guides/professional-outputs) says the Magnific Video Upscaler "raises the video to 4K. Inputs can be at most 30 seconds." Its `creativity` setting is "How much AI-generated detail to add during upscaling, from 0 (faithful) to 100." Our advice: keep it low on approved work, so no new detail appears.

Enhance Frame Rate changes a clip to a set frame rate (frames per second), such as 25. "Inputs can be at most 300 seconds."

On Google, Omni marks its 1080p and 4K outputs as "upscaled". The [Veo page](https://ai.google.dev/gemini-api/docs/veo) says Veo 3.1 "can also directly generate 720p, 1080p or 4k videos".

### HDR is its own delivery

The Runway docs: "HDR (high dynamic range) stores a wider span of brightness than standard dynamic range (SDR)."

- **Runway.** Gen-4.5 "can generate HDR natively". Ruby "converts any SDR video, including an Aleph edit, to HDR". Its inputs "must be SDR, at most 30 seconds, and up to 4K".
- **Luma.** `hdr: true` "generates an HDR-encoded MP4". It "requires 720p or 1080p" and "is not supported with duration: "10s" or loop". `exr_export` adds an EXR file "for professional colour-grading workflows" and "Requires hdr: true".

### File formats for the next person

On Gen-4.5 and Aleph 2.0, Runway's `outputFormat` sets the file:

| Value              | What you get                                                   |
| ------------------ | -------------------------------------------------------------- |
| `mp4` (default)    | an H.264 .mp4                                                  |
| `prores`           | a ProRes .mov (a high-quality format for editing programs)     |
| `png_sequence`     | a .zip of PNG frames, plus a separate .wav when there is sound |
| `sdr_rec709_10bit` | a 10-bit Rec.709 .mp4                                          |

The 10-bit file is for when "a grade needs more precision than 8-bit H.264". (A grade is a colour adjustment.) "That file is still SDR."

Two traps from the Runway docs:

- ProRes and PNG files "stay in standard dynamic range. HDR is a separate delivery."
- ProRes 4444 is the default profile. In the API reference, its alpha channel (the part that stores see-through areas) "is present but fully opaque; choose these tiers for 12-bit 4:4:4 color fidelity, not for mattes". (A matte is a file with see-through parts.)

### Keep the source

The Luma docs say: "The generation id does not expire — keep it if you plan to edit, extend, or reframe the video later." Download links "expire after 1 hour".

## Worked example

The museum master: 16:9, 10 seconds, painting on the left third.

### Step 1: the weak plan

```json
{
  "model": "ray-3.2",
  "type": "video_reframe",
  "source": { "generation_id": "<master id>" },
  "aspect_ratio": "1:1",
  "prompt": "Make it square."
}
```

### Step 2: the hard case

**The hard case is the painting's place.** With no `source_position`, Luma uses a centered crop. A square cut from the middle of a wide frame loses the left and right edges, and the painting is on the left.

So we place the whole master inside the square and let Luma fill above and below. Our maths: the master is 16 wide and 9 high. If it fills the full width of a square, its height is 9 ÷ 16 = 0.5625 of the square. To centre it, the top edge sits at (1 − 0.5625) ÷ 2 = 0.21875.

### Step 3: the fixed request

```json
{
  "model": "ray-3.2",
  "type": "video_reframe",
  "source": { "generation_id": "<master id>" },
  "aspect_ratio": "1:1",
  "prompt": "Extend the gallery wall above and the wooden floor below, in the same soft light.",
  "video": {
    "duration": "10s",
    "resolution": "1080p",
    "source_position": { "x_norm": 0, "y_norm": 0.21875, "w_norm": 1, "h_norm": 0.5625 }
  }
}
```

1080p is fine here, because the target is square, not vertical. `duration` is 10 seconds to keep the whole master.

### Step 4: the delivery sheet

This format is ours:

```text
File            Ratio  Size   Range  Format          Source id
feed-square     1:1    1080p  SDR    MP4             <reframe id>
social-master   16:9   1080p  SDR    MP4             <master id>
```

Download each file the same day, and keep both ids.

### Step 5: why it is better

- **The painting stays in the frame**, because we chose where the master sits.
- **The approved motion is untouched.** Reframe keeps the source frame for frame.
- **Every file has a source id**, so you can redo any step later.

## Common mistakes

1. **A new take when the motion is approved.** The client sees a different clip. Fix: outpaint with a reframe, and save new takes for new layouts.
2. **Trusting the default centered crop.** An off-centre subject gets cut. Fix: set `source_position` so the subject stays in the canvas.
3. **Keeping only the download link.** On Luma it expires after an hour. Fix: download the same day and keep every generation id.

## Try it

Not graded. Write your answer down before you read the answer.

Pick an output for each person, and give one reason.

1. The social team wants a file to post today.
2. A colourist wants a Runway Gen-4.5 clip in standard range, but with more precision than a normal MP4.
3. A grader asks for an EXR file next to an HDR MP4 from a 5-second Luma clip.
4. A TV channel needs a clip at exactly 25 frames per second.

### Answer

1. **`mp4`**, the default H.264 file. Social media needs nothing more.
2. **`sdr_rec709_10bit`.** It is for a grade that needs more precision than 8-bit H.264, and it is still SDR.
3. **Luma `hdr: true` with `exr_export: true`**, at 720p or 1080p. EXR "Requires hdr: true", and HDR does not work at 10 seconds, so a 5-second clip fits.
4. **Runway Enhance Frame Rate** with a target of 25. It sets the frame rate of a clip you already have.

## Recap

- Crop, outpaint or regenerate on purpose. A reframe keeps the master frame for frame. Use `source_position` when the subject is not in the centre.
- Know the reframe limits: six ratios, 10 seconds in and out, vertical 1080p not yet, standard range only.
- Upscale with low creativity, treat HDR as its own delivery, pick the format for the next person, and keep every id.
