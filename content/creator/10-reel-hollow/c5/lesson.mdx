## Goal

After this lesson you can:

- Turn one approved still into a short clip, and tell the model how to use the image.
- Make a seamless loop with a tool that supports it, using motion that can come back to its start.
- Keep what the client approved: the product's sides, its text and its look.

## The problem

A plant shop has one approved photo: a fern in a white pot on a sunny windowsill. The shop's name is painted on the pot. The shop wants a "living photo" for its website: the same picture, but the leaves move a little.

A text prompt alone draws a new fern and a new pot every time. The client approved this photo, not a new one. The job is to add motion and lose nothing.

## The idea

### When a still beats text

Our rule: start from a still when the look is already approved. Start from text when nothing is approved and you want ideas.

The vendors point the same way:

- The [Gemini API docs](https://ai.google.dev/gemini-api/docs/veo) say Veo "uses the input image as the initial frame". Pick the image "closest to what you envision as the first scene".
- The [Runway docs](https://docs.dev.runwayml.com/recipes/product-ad) for the Product Ad recipe say: "let the product images define what the product looks like."
- The [Omni page](https://ai.google.dev/gemini-api/docs/omni) says image to video "is useful for bringing product shots, illustrations, or photographs to life".

### Say how the image is used

Models use your image in different ways (October 2026):

| Model             | How the image is used                   |
| ----------------- | --------------------------------------- |
| Veo 3.1           | the first frame (`image`)               |
| Runway `gen4.5`   | the first frame (`position` is `first`) |
| Luma `ray-3.2`    | `start_frame`, `end_frame`, or both     |
| Gemini Omni Flash | the model decides, from your prompt     |

On Omni, "Depending on your prompt, the model will decide how to use the image." So say it. The Gemini API docs give guiding lines for the end of a prompt:

- "Use this image as the starting frame."
- For reference images: "The images should not be used as literal initial frames."

Then describe the motion. The docs warn: "Vague prompts like "make it move" produce less compelling results than detailed descriptions of the camera movement, subject motion, and environmental effects."

### Seamless loops

A **seamless loop** is a clip whose end flows back into its start. It can repeat with no visible jump, which suits a web header.

**Luma.** Set `video.loop: true`. The [Luma docs](https://docs.agents.lumalabs.ai/guides/videos/generation) say it "generates a seamlessly looping video". The rules:

- "loop is create-only — valid for type: "video" only; rejected on type: "video_edit"."
- "It is not supported with duration: "10s", hdr: true, or end_frame."
- `keyframes` is "mutually exclusive with start_frame, end_frame, and loop".

So a loop from a still on Luma is: `start_frame` set to the still, `loop: true`, 5 seconds, no HDR. (HDR, high dynamic range, stores a wider range of bright and dark.)

**Omni.** Give one image both frame roles: first and last. The docs say `[# Sources <FIRST_FRAME>@Image1 <LAST_FRAME>@Image1]` "will use the first image as both the first frame and the last frame, creating a video that loops". The guiding line: "Use this image as the first frame and the last frame."

Our advice: for any other model, check its reference for a loop setting before you promise a loop.

### Motion that can come back

The last frame of a loop has to match its first. So choose motion that returns (our advice):

- **Loops well:** steam, a slow light sweep, leaves in a light wind, water ripples.
- **Loops badly:** a camera that travels. It ends in a new place, so each repeat jumps back.

A small comparison: a good loop is like a swing. It goes out and comes back to the same spot.

Check a loop by playing it three times in a row. Watch the join.

### Product turns need more views

A **product turn** shows a product from more than one side. A photo of the front alone hides the back. Our reading: the model must invent it.

The Runway Product Ad tips ask for reference images "from multiple angles — front, back, and sides". The docs add: "The first image is used as the primary product reference."

Our advice: have the client approve stills of the sides and the back before you plan the turn. If only the front is approved, keep the move small, such as a slow quarter arc.

### Text, logos and holds

The Omni page says the model can render text "in a way that is correct and readable". It adds: "If there will be naturally occurring text in your video, even in background elements, it can help to define what it should say."

For a logo that must be exact, our advice is stricter: animate around it and keep it still, or animate a clean card and add the true logo file later, in the editing app. Letters can bend in the middle of a clip, so check every frame.

Before you write the prompt, list what **holds** (product, label, colours, framing) and what may **move** (leaves, steam, light). Write the holds into the prompt (our method).

## Worked example

The fern photo again. The website wants a 6-second living photo. It does not need to loop.

### Step 1: the weak prompt

```text
Image: fern-approved.jpg
Prompt: A beautiful fern plant in a pot, cinematic, lots of movement,
        camera flies around the plant.
```

It describes the plant again, asks for a big camera move, and says nothing about what must stay.

### Step 2: list holds and moves

```text
Holds:  the pot, the painted shop name, the window frame, the framing
Moves:  fern leaves (small sway), sunlight (slow shift), dust in the light
```

The client approved the framing, so the camera stays still. The motion lives in the small things.

### Step 3: the request on Veo 3.1

```text
image:  fern-approved.jpg   (the first frame)
durationSeconds: "6"
prompt: Static shot. The fern's leaves sway gently in a light breeze
        from the open window. Sunlight shifts slowly across the leaves,
        and dust drifts in the light. The white pot, the window frame
        and the painted text on the pot do not move or change.
        Quiet room sound, a bird outside.
```

### Step 4: the hard case

**The hard case is the painted shop name.** It is text inside the picture, and the model draws every frame again. We name it exactly, following the Omni advice to define what text should say:

```text
The pot has the words "Green Corner" painted on it in black letters.
The words stay sharp and the same in every frame.
```

Then we check the first frame, the middle and the last against the photo, and step frame by frame across the words. If a letter bends, we do not ship the clip.

### Step 5: why it is better

- **The approved look holds**, because the photo is the first frame and the prompt lists the holds.
- **The motion is small and specific**, so the model has less to invent.
- **The text has a plan** and a check.

## Common mistakes

1. **Describing the whole scene again.** The model may redraw what you approved. Fix: name the holds, then describe only the motion.
2. **A big camera move on an approved frame.** The framing the client liked is lost. Fix: keep the camera static and move small things.
3. **Skipping the middle of the clip.** Drift often starts there. Fix: compare start, middle and end with the still.

## Try it

Not graded. Write your answer down before you read the answer.

For each job, choose: start from text, use the image as the first frame, or use the image as a reference. Give one reason.

1. A new tea brand has no approved look yet. It wants ten very different ideas for a launch clip.
2. A lamp shop has an approved photo of its lamp. The clip must open on exactly that photo.
3. A shoe brand has an approved photo of a sneaker. The clip opens on a city street, and the sneaker appears later on a runner's foot.

### Answer

1. **Text.** Nothing is approved, so ideas matter more than a fixed look.
2. **First frame.** Veo uses the image as the initial frame, Luma takes it as `start_frame`, and Runway `gen4.5` takes it at `position` `first`.
3. **Reference.** The photo should guide how the sneaker looks, not be the opening picture. On Veo 3.1, `referenceImages` takes "Up to three images to be used as style and content references". On Omni, add the line "The images should not be used as literal initial frames."

## Recap

- Start from the approved still, say how the image is used, and describe specific motion. List the holds and write them into the prompt.
- Loop only with a tool that supports it: Luma `loop: true` (5 seconds, no HDR, no end frame, no keyframes) or one image in both the first-frame and last-frame roles on Omni. Pick motion that comes back.
- Get more views approved before a product turn, and name or hand-place any exact text.
