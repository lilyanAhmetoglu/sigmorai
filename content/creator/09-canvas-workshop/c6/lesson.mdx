## Goal

After this lesson you can:

- Export files from Figma and Canva with the right settings, and read what comes back.
- Say what links design components and tokens to code, and who may use it.
- Check plans, seats and expiry rules before you promise a handoff.

## The problem

You design an app for a city's bike-share service. The screens are done. A web developer needs two things from you:

- the map icons as SVG files (a vector format that stays sharp at any size)
- a small chart graphic whose labels must be real, selectable text, so they can be translated later

Last time, the SVG labels came out as shapes, and the translator could not select them. The icons had no layer names inside, so the developer could not find the parts.

This lesson covers what a good handoff needs: export settings, link rules and the link from design to code.

## The idea

### Figma: export images with the REST API

The **REST API** is the web API a script calls from outside Figma. The [Figma docs on file endpoints](https://developers.figma.com/docs/rest-api/file-endpoints/) describe GET image. It returns a map "from node IDs to URLs of the rendered images" (a **node** is one item in the file, like a frame or an icon).

Rules from that page:

- "The image assets will expire after 30 days."
- "Images up to 32 megapixels can be exported. Any images that are larger will be scaled down."
- `scale` is "A number between 0.01 and 4". `format` is `jpg`, `png`, `svg` or `pdf`.
- "the image map may contain values that are null. This indicates that rendering of that specific node has failed." For example, "a node that is invisible or has 0% opacity cannot be rendered."

Three SVG settings matter for a handoff:

| Setting               | Default | What it does                                                                                                      |
| --------------------- | ------- | ----------------------------------------------------------------------------------------------------------------- |
| `svg_outline_text`    | true    | text as outlines (shapes), or as `<text>` elements                                                                |
| `svg_include_id`      | false   | "Adds the layer name to the id attribute of an svg element."                                                      |
| `use_absolute_bounds` | false   | "Use the full dimensions of the node regardless of whether or not it is cropped or the space around it is empty." |

On outlines, the page says: "Rendering text elements as outlines guarantees that the text looks exactly the same in the SVG as it does in the browser/inside Figma." On `<text>`, it says this "allows text to be selectable inside SVGs", but "visual accuracy is not guaranteed".

The Figma MCP server has its own export tool. The [Figma tools page](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/) says `download_assets` returns "temporary URLs that must be fetched to retrieve file contents".

### Canva: exports and their links

The [Canva docs on get-export-formats](https://www.canva.dev/docs/apps/mcp/tools/get-export-formats/) say to call it before an export. It returns only "the formats this design supports". Each format can list `page_numbers`; "when `page_numbers` is omitted, every page supports the format."

The [Canva docs on export-design](https://www.canva.dev/docs/apps/mcp/tools/export-design/) say: "Signed export URLs expire. Use them immediately, and don't store or share them." (A **signed URL** is a download link with a built-in key.)

The [Canva tools page](https://www.canva.dev/docs/apps/mcp/tools/) adds plan rules. Export works on all plans, but:

- "**Free plans:** Standard quality export"
- "**Canva Pro and above:** Pro quality with lossless PNG, transparent backgrounds, and premium element export"
- "If a design contains premium elements, export may fail with `license_required`"

The [Canva handoff page](https://www.canva.dev/docs/apps/mcp/workflows/design-edit/) warns: "Don't end the workflow at export." About an export it says: "It's a delivery mechanism, not a handoff." Offer the edit link too.

### From design to code: Code Connect

The [Figma page on what the server does](https://developers.figma.com/docs/figma-mcp-server/mcp-vs-agent/) says the server "won't know your conventions or strategies unless you provide that information through Code Connect, variables or prompts."

The [Code Connect introduction](https://developers.figma.com/docs/code-connect/) says it connects "components in your repositories directly to components in your design files". It is "Available on a Dev or Full seat on the Organization, and Enterprise plans".

When a frame has connected components, the [Figma docs on Code Connect and the MCP server](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/) say the server adds `<CodeConnectSnippet>` wrappers. They hold design properties, "Import statements", the "Component snippet" and any custom instructions.

There are two ways to set it up. The [Figma comparison page](https://developers.figma.com/docs/code-connect/comparing-cc/) says:

| What the MCP server gets | Code Connect CLI                                    | Code Connect UI                           |
| ------------------------ | --------------------------------------------------- | ----------------------------------------- |
| Context                  | path, name, property mapping, dynamic code examples | path, name, user prompt, codebase context |
| Where you set it up      | locally in the repository, from the terminal        | inside Figma                              |

The same page says the UI "doesn't yet support property mapping or dynamic examples". The [Figma write-to-canvas page](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/) also lists: "Components must be manually published before Code Connect completes".

### Tokens: the Variables REST API

**Variables** are named values in Figma, like colours and spacing (often called design tokens). The [Figma Variables REST API page](https://developers.figma.com/docs/rest-api/variables/) says: "To use this API, you must have a Full seat in an Enterprise org; guests cannot use the API." Reading needs "View access" for "Any organization member"; writing needs "Full seats, admins" and "Edit access". The [Figma variables endpoints page](https://developers.figma.com/docs/rest-api/variables-endpoints/) lists "Limited by Figma plan" as one possible 403 error.

A comparison: an export is a photo of a dish. Code Connect and variables are the recipe card.

## Worked example

The bike-share handoff from the problem. The node names are our example.

### Step 1: the weak export

```text
GET /v1/images/:key?ids=icon_dock,icon_bike,icon_pin,chart_trips&format=svg
```

All settings stay at their defaults. What comes back:

- The chart labels are outlines (the default), so nobody can select or translate them.
- The SVG elements have no layer names, so the developer cannot find the parts.
- `use_absolute_bounds` is off. Our reading: the empty space around an icon may not be kept.

### Step 2: split the request by job

```text
Icons:
GET /v1/images/:key?ids=icon_dock,icon_bike,icon_pin
    &format=svg&svg_include_id=true&use_absolute_bounds=true

Chart:
GET /v1/images/:key?ids=chart_trips
    &format=svg&svg_outline_text=false&svg_include_id=true
```

Simplified. See the docs for the exact request shape.

`use_absolute_bounds` keeps the full frame of each icon, empty space included. `svg_include_id` puts the layer names into the SVG, so the developer can find `wheel` or `label`.

### Step 3: the hard case, look or selectable text

**This is the hard part.** The chart needs real text for translation. But the page warns that `<text>` "relies on the browser's rendering engine", so the look may change between browsers.

So you choose per asset. Our advice:

- **Chart labels:** `<text>`. Translation needs real text. Check the chart in two browsers before you sign it off.
- **The service's logo wordmark:** keep outlines. Its shape must never change, and nobody translates a logo.

### Step 4: why it is better

```text
Weak                           Better
one request, all defaults ->   icons and chart exported with their own settings
labels as outlines        ->   labels as text, checked in two browsers
no layer names            ->   layer names as SVG ids
icon edges may be trimmed ->   full frame of each icon
```

## Common mistakes

1. **Exporting before you check the formats.** Some pages may not support a format. Fix: call `get-export-formats` first, and use a listed key.
2. **Promising a transparent PNG on a Free plan.** Canva lists transparent backgrounds for Pro and above. Fix: check the plan before you promise.
3. **Turning every SVG text into `<text>`.** The look is not guaranteed. Fix: keep outlines when the exact shape matters more than editing.

## Try it

Not graded. Write your answer down before you read the answer.

A teammate wants the three pages of a Canva promo design as MP4 videos. `get-export-formats` returns:

```text
pdf  pages 1, 2, 3
png  pages 1, 2, 3
mp4  pages 3
```

1. Which pages can be exported as MP4?
2. What `format` value goes into `export-design`?
3. The export returns `license_required`. What is the likely cause?

### Answer

1. **Only page 3.** It is the only page listed under `mp4`.
2. **`mp4`.** The docs say to use a listed key as the `format` value.
3. **A premium element in the design.** The tools page says export may fail with `license_required` when a design contains premium elements.

## Recap

- Figma GET image: links expire after 30 days, images over 32 megapixels are scaled down, and null means that node did not render. Pick SVG settings per asset.
- Canva: check formats first, use signed export URLs at once, and hand over the edit link too, not only the export.
- Code Connect (Dev or Full seat, Organization or Enterprise) sends real components to the agent; only the CLI adds property mapping. Variables through the REST API are for Enterprise orgs only, and guests are left out.
