## Goal

After this lesson you can:

- Name what each Figma read tool sends to an AI assistant, and pick the one you need.
- Say why a picture of a design is a weak spec, and what to send with it.
- Write a request that works on the remote server, in your team's framework, with the motion included.

## The problem

You design a ticket app for a theatre. The app is built in Vue. A developer asks an AI assistant to build your new "seat saved" toast (a small message that slides in and fades out).

Three things go wrong:

- The code comes back in React, a framework (a set of code building blocks) the app does not use.
- The toast appears and stays. Your slide and fade are gone.
- On a second try, the developer types "build my selection". The assistant gets nothing.

The question is simple: what does the assistant really get from your file?

## The idea

### What a design server is

An **MCP server** is a plug that lets an AI assistant call tools in another app. Figma's read tools pull information out of your file. The assistant writes the code.

The [Figma docs on what the server does](https://developers.figma.com/docs/figma-mcp-server/mcp-vs-agent/) are clear: the server "is not a one-click 'design to perfect code' tool". It "acts as a bridge between Figma and your IDE" (the developer's code editor). Two things it does not do:

- "Generate final code. That's your AI assistant's role."
- "Understand your design system by default. It won't know your conventions or strategies unless you provide that information through Code Connect, variables or prompts."

**Code Connect** maps a part of your Figma design to a component in your code.

### The read tools

The [Figma tools page](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/) groups them as "Design to code". It calls `get_design_context` "the default entry point".

| Tool                 | What it sends                                                               |
| -------------------- | --------------------------------------------------------------------------- |
| `get_design_context` | code for a layer or selection; "By default, the output is React + Tailwind" |
| `get_metadata`       | "a sparse XML representation" (a short text outline)                        |
| `get_variable_defs`  | "the variables and styles used in your Figma selection"                     |
| `get_screenshot`     | a picture of your selection                                                 |
| `get_motion_context` | "keyframe animation data for an animated node"                              |
| `download_assets`    | exports and the original uploaded images, as temporary URLs                 |

A **variable** is a named value in your file, like a colour or a space. A **layer** is one object in your file. A **keyframe** is a saved point in an animation. **CSS** is the code that sets how a web page looks, and **Tailwind** is a CSS style kit.

The details matter:

- **Design context** can change shape. The default is React + Tailwind, "but you can customize it through your prompt". One example request from the page: `generate my Figma selection in Vue`. You can also name your own components folder.
- **Metadata** holds "just basic properties such as the layer IDs, names, types, position and sizes". The page says the agent can "break down and call get_design_context on" the parts it needs. It is "Useful for very large designs".
- **Variables** cover "colors, spacing, and typography". The [Figma page on picking tools](https://developers.figma.com/docs/figma-mcp-server/trigger-specific-tools/) says the assistant "doesn't automatically pick the right one". So name the tool or the output in your prompt. The page's own example is `Get the variable names and values used in this frame`.
- **The screenshot** "helps preserve layout fidelity in the generated code" (how close the layout stays). The page says it is "Recommended to keep on: only turn it off if you're concerned about token limits". Here a **token** is a unit of text the model reads, not a design token.
- **Motion** comes after the static part. The page says to call `get_motion_context` "after get_design_context when a design contains animation", and to "Pass the same node id". A **node** is one item in the file, like a frame.
- **Assets.** The page says: "Use get_screenshot when the agent needs to see what a design looks like. Use download_assets when the agent needs to deliver an asset to the user, export in a specific format, or transfer images between files."

### Remote or desktop

Figma runs the server in two ways: in the desktop app, or as a remote server on the web. The tools page warns: "Selection-based prompting only works with the desktop MCP server. The remote server requires a link to a frame or layer to extract context."

### A picture is not a spec

A screenshot shows the look. It does not carry the names behind the look. The vision pages of two vendors say so:

- The [OpenAI docs on vision](https://developers.openai.com/api/docs/guides/images-vision): "The model doesn't process original file names or metadata."
- The [Claude docs on vision](https://platform.claude.com/docs/en/build-with-claude/vision): "No, Claude does not parse or receive any metadata from images passed to it."

The same pages list other limits:

- The OpenAI docs: the model "struggles with tasks requiring precise spatial localization".
- The Claude docs: "coordinate and localization outputs are approximate".
- The Claude docs: a large image may be resized, which "might, for example, make text less legible".

Our reading: a picture answers "what does it look like?". The file answers "which variable, which component, how much space?". A comparison: a photo of a cake shows the cake. The recipe tells you how to make it.

### Keep each request small

The [Figma page on large frames](https://developers.figma.com/docs/figma-mcp-server/avoid-large-frames/) warns that large selections "can slow the tools down, cause errors, or result in incomplete responses". Its advice: "Generate code for smaller sections or individual components (e.g. Card, Header, Sidebar)".

### Make the file readable

The [Figma page on file structure](https://developers.figma.com/docs/figma-mcp-server/structure-figma-file/) gives the designer's part:

- **Components.** "anything repeated should be a component."
- **Variables.** "Apply variables for spacing, color, radius, and typography."
- **Names.** "Replace default names (Frame1268, Group5) with intent-driven ones".
- **Auto Layout** (Figma's tool for frames that resize with their content). It helps "communicate layout intent clearly".
- **Annotations** (notes pinned to a layer). They carry intent "that's hard to capture from visuals alone, like how something should behave, align, or respond."

### Canva reads text only

Canva's MCP server has a read tool too. The [Canva docs on get-design-content](https://www.canva.dev/docs/apps/mcp/tools/get-design-content/) say it reads "a design's text content for read-only inspection". It "Returns the text as a single `text` field plus `metadata`". The docs add: "This response is for reading content, not for targeting edits." The IDs you can edit come from a different tool, `start-editing-transaction`.

## Worked example

The task: the "seat saved" toast from the problem. The developer uses Figma's **remote** server. The app is Vue, with shared parts in `src/components/ui`.

### Step 1: the weak request

```text
Build my selection.
```

What happens:

- The remote server has no selection to read. Selection prompts only work on the desktop server.
- Even with a link, the code would come back in the default, React + Tailwind.
- Design context is the static frame. The slide and fade are not in it.

### Step 2: give the server a target

Paste the link to the toast frame. Then name the framework and the components folder.

```text
Using this frame: <link to the SeatSavedToast frame>
Generate it in Vue, using components from src/components/ui.
```

The wording follows the docs' example requests.

### Step 3: the hard case, the motion

**This is the hard part.** The toast looks fine as a still frame. But the brief is the movement: slide in, wait, fade out. A still picture or the static code cannot show it.

The tools page gives the order: design context first, then motion, on the same node.

```text
Then call get_motion_context on the same node id,
and add the slide-in and fade-out to the Vue component.
```

Simplified. See the docs for the exact request shape.

The page says the motion answer includes "keyframe tracks with easing curves" (the speed shape of a move) and ready CSS `@keyframes`. So the developer gets your real timing, not a guess.

### Step 4: say what the still frame cannot

The toast has one rule that no tool can see: it must not cover the "Pay" button. Put that in an **annotation** on the frame, before the handoff. The structure page names behaviour as the kind of intent that annotations carry.

### Step 5: why it is better

```text
Weak                         Better
no link (remote server)  ->  link to one frame
default React + Tailwind ->  Vue + your components folder
static frame only        ->  get_motion_context, same node
behaviour in your head   ->  annotation on the frame
```

Each change gives the assistant a fact it could not guess.

## Common mistakes

1. **Using "my selection" on the remote server.** It only works on the desktop server. Fix: paste the link to the frame.
2. **Forgetting to name the framework.** The output is React + Tailwind unless you ask. Fix: write the framework and your components folder in the prompt.
3. **Using get_screenshot to send files.** It is for looking. Fix: use `download_assets` to deliver an export or an original image.

## Try it

Not graded. Write your answer down before you read the answer.

You work on a Figma file for a music festival app. Pick one Figma tool for each need:

1. The printer wants the original photo you placed in the hero frame, as the file you uploaded.
2. A developer must rebuild the bouncing "ticket added" icon with the same timing.
3. A developer wants to see what the lineup screen looks like before building it.

### Answer

1. **`download_assets`.** It returns the original uploaded images, not a new render. A screenshot is a new picture of the design, not the file you uploaded.
2. **`get_motion_context`,** after `get_design_context` on the same node. It returns the keyframes and easing.
3. **`get_screenshot`.** The docs say to use it when the agent needs to see what a design looks like.

## Recap

- The Figma server carries input; the assistant writes the code. Each read tool sends a different part: design context, outline, variables, picture, motion, assets.
- A picture carries no names. Send structure from the file, keep each request small, and make the file readable with components, variables, names, Auto Layout and annotations.
- Say exactly what you want: a link on the remote server, your framework, and the right tool. Canva's text read is for reading, not for edits.
