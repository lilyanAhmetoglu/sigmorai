## Goal

After this lesson you can:

- Pick the right Firefly operation for a job: expand, fill or one of three composites.
- Paint and read a mask, and say where a photo sits in a bigger frame.
- Run an image job from start to file, and plan for its limits and its expiry dates.

## The problem

You are an illustrator. A publisher approved your square cover art for a new novel. Now marketing wants it in more shapes: a wide banner for the website and a tall version for phone stories. Somebody suggests: "Just ask the AI to make it wider."

A developer writes a small script for Adobe's Firefly API (a web service that edits images with AI). The first run gives no images at all. The script printed a job number and stopped. A week later the team runs it again for a new size, and it fails in a new way.

This lesson shows which operation fits which job, and how an image job really runs.

## The idea

### Four kinds of edit

The [Adobe Firefly API docs](https://developer.adobe.com/firefly-services/docs/firefly-api/) cover several image operations. Three matter most here:

- **Expand.** The [Expand tutorial](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/how-tos/firefly-expand-image-api-tutorial) says it can "Generatively expand an image out beyond its edges". Its own example turns one picture into sizes for different social platforms.
- **Fill.** The [Fill tutorial](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/how-tos/firefly-fill-image-api-tutorial) says it can "Generatively edit specific areas of an image". Its example replaces the backgrounds of employee photos.
- **Composite** (putting one object into a scene). See below.

### Masks: which parts may change

A **mask** is a black and white picture laid over your image. The [Adobe docs on masks](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/concepts/masking/) say:

- "Black areas are protected. No requested edits will apply to these regions."
- "White areas are exposed. Requested edits will apply only to these regions."

The page compares white areas to "beams from flashlights". An **inverted** mask swaps the two colours, so the protected part becomes the editable part.

Other vendors work differently:

- The [OpenAI docs on image generation](https://developers.openai.com/api/docs/guides/image-generation) say: "The mask image must also contain an alpha channel." (An **alpha channel** is the see-through layer of a PNG.) The image and mask "must be of the same format and size". And: "Masking with GPT Image is entirely prompt-based. The model uses the mask as guidance, but may not follow its exact shape with complete precision."
- The [Gemini docs on image generation](https://ai.google.dev/gemini-api/docs/image-generation) describe "Inpainting (semantic masking)": you say in words which part to change, and no mask file is sent.

### Placement: where the photo sits

When you expand, the old photo must sit somewhere in the new, bigger frame. The [Adobe docs on placement](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/concepts/placement/) say it controls "how an image is positioned and sized in the final generation". Two options:

- **Alignment**, for example `"horizontal": "left"`, pins the photo to one side. The new image grows on the other side.
- **Inset** sets "margins (in pixels) from each side of the frame".

### Three composites

The [Adobe composite guide](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/how-tos/object-composite/) names three operations:

| Operation                 | Use when                                            |
| ------------------------- | --------------------------------------------------- |
| Generate Object Composite | "no background image exists yet"                    |
| Precise Composite         | "the subject must not be altered"                   |
| Adaptive Composite        | "realism and seamless integration are the priority" |

Adaptive Composite works "by adapting and regenerating the subject to match the scene". So the object itself may change.

### Jobs, uploads and limits

**Async jobs.** These calls are **asynchronous**: the result comes later. The [Adobe async guide](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/how-tos/using-async-apis) gives the order:

```text
1. send the request
2. get back jobId, statusUrl, cancelUrl  (no image yet)
3. check statusUrl again and again       ("running")
4. "succeeded" or "failed"
5. on success, download from the result URL
```

The guide's example says to "check once every second and wait for a success or failure message".

**Uploads.** The [Adobe upload page](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/concepts/image-upload/) says: "The upload id is valid for 7 days from the date of upload." Supported formats are JPEG, PNG and WebP.

**Rate limits.** The [Adobe usage notes](https://developer.adobe.com/firefly-services/docs/firefly-api/getting-started/usage-notes/) give the default limits "per organization":

- "4 requests per minute (RPM)"
- "9,000 requests per day (RPD)", for organizations that got a higher per-minute limit

Over the limit, "you'll receive an HTTP 429 Too Many Requests error". The page's fixes: reduce requests, "Implement retry logic via a retry-after HTTP header or an exponential backoff strategy" (wait longer after each failed try), or ask your account manager for more.

### Resize the layout, expand the photo

Not every size change needs AI pixels. The [Canva docs on resize-design](https://www.canva.dev/docs/apps/mcp/tools/resize-design/) say it creates "a copy of an existing design at new dimensions, with the layout rearranged to fit". Also: "The original is unchanged. It isn't for resizing a single element within a page." It needs a plan "with premium features, such as Canva Pro".

A comparison: resize moves the furniture into a new room. Expand paints more wall.

## Worked example

The cover art from the problem. The size and dates are our example.

### Step 1: the weak script

```text
2 June
  upload cover.png            -> uploadId U1   (saved in the config file)
  expand to 1024x512 (U1)     -> answer: jobId, statusUrl, cancelUrl
  script: "Done!"             (prints the jobId and stops)
```

Two problems:

- The answer to an expand call is a job, not a picture. Nobody asked the `statusUrl`.
- The upload ID is saved "for later", with no date.

### Step 2: follow the job to the end

```text
expand to 1024x512 (U1)  -> jobId J1, statusUrl
check statusUrl           -> "running"
check again (1 s later)   -> "running"
check again               -> "succeeded", result.outputs[0].image.url
download the file         -> banner_1024x512.png in your storage
```

Simplified. See the docs for the exact request shape.

Now the script stops only on `succeeded` or `failed`, and it saves the real file.

### Step 3: the hard case, the next week

**This is the hard part.** On 11 June, marketing asks for the tall phone story. The script still has `U1` in its config.

Count the days. `U1` was made on 2 June. The upload page says an upload ID is valid for 7 days. On 9 June `U1` reached 7 days. On 11 June it is 9 days old, so it is no longer valid.

Our advice: store the upload date next to each ID. Before each run, upload again if the ID is 7 or more days old.

```text
11 June
  U1 is 9 days old  -> upload cover.png again -> U2
  expand to 1080x1920 (U2) -> poll -> "succeeded" -> download
```

### Step 4: one more check by eye

The story is much taller than the square art. Expand invents all the new space above and below. Our advice: a person checks that the new areas fit the art before anything goes to the publisher.

### Step 5: why it is better

```text
Weak                           Better
stops at the jobId        ->   polls to succeeded or failed
image link not saved      ->   file downloaded and stored
upload ID used forever    ->   ID dated, re-uploaded after 7 days
```

## Common mistakes

1. **Reading the first answer as the image.** An async call returns a job. Fix: poll `statusUrl` until it says succeeded or failed.
2. **Using a layout resize for one picture.** Canva's `resize-design` changes the whole design, not one element. Fix: resize the layout there, and expand only the photo.
3. **Trusting the exact edge of an OpenAI mask.** OpenAI says the mask is only guidance. Fix: check the edges of every result by eye.

## Try it

Not graded. Write your answer down before you read the answer.

A children's book studio has three jobs:

1. A Canva poster with a title, text and art must also exist as a 16:9 slide.
2. A single square illustration needs more sky at the top for a tall print.
3. The team wants to edit a photo with Gemini, but nobody can paint masks.

Which tool or way of working fits each job?

### Answer

1. **Canva `resize-design`.** It makes a copy at the new size with the layout rearranged. The poster stays as it was.
2. **Firefly Expand.** It grows a picture past its edges. The layout tool would not add new sky to one picture.
3. **Describe the change in words.** The Gemini docs show semantic masking: the prompt says which part to change, with no mask file.

## Recap

- Expand grows an image past its edges. Fill changes only the white part of a mask; black is protected. Composites put an object into a scene, and Precise Composite keeps the subject unchanged.
- Placement decides where the old photo sits in the new frame: alignment or inset.
- Image jobs run async: poll to the end and save the file. Upload IDs last 7 days, and the default limit is 4 requests per minute, with 429 when you go over.
