## Goal

After this lesson you can:

- Say where an AI edit lands in Figma and in Canva, and what you need before it can land.
- Run a Canva edit in its three steps, read the status of each step, and know when it is really saved.
- Set up approvals so a person sees a write before it happens.

## The problem

You keep the website for a city museum as a responsive Canva design (a design whose layout changes with the screen size). The summer show changes its name. The new name must appear in the headline and in three section titles.

You ask an AI assistant to do it. It answers: "Updated!" You open the page. The headline is new. One section title still has the old name. Nobody can say which step went wrong, because nobody looked at the steps.

This lesson shows what each step of an AI edit returns, and how to check it.

## The idea

### Figma: the agent writes into the file

An **MCP server** is a plug that lets an AI assistant call tools in another app. Figma's write tool is `use_figma`. The [Figma tools page](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/) calls it "General-purpose create, edit, and inspect". It is marked as remote-only (it works on the web server, not the desktop one). The page adds that the write tools "work best with a skill", and names `figma-use` for Figma Design. (A **skill** is a set of instructions the agent loads before it uses the tools.)

The [Figma write-to-canvas page](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/) explains how:

- "Write to canvas works by letting your client execute JavaScript in the context of a Figma file through the Plugin API."
- The result is real frames, components and auto layout, "rather than generating a screenshot or static export".
- The tools page adds: "When relevant, the agent will first check your design system or existing file content before creating anything from scratch."

**Seats.** A seat is the kind of Figma licence a person has. The write page says: "You need a Full seat to write to Figma files with agents. Dev seat holders can use the Figma MCP server for read-only workflows such as pulling design context, variables, and screenshots. To modify an existing file, you also need edit permission for that file."

**Limits.** The write page lists "Current limitations". When this lesson was written (October 2026) they were:

- "20kb output response limit per call"
- "No assets (image) support yet"
- "Custom fonts aren't supported yet"
- "Components must be manually published before Code Connect completes"

The tools page does not fully agree on images:

- It says `use_figma` "can work with pages, frames, components, variants, variables, styles, text, images, and more".
- It lists a separate remote-only tool, `upload_assets`: "Uploads assets (PNG, JPG, GIF, and WebP) into a Figma file. Max 10MB per asset."
- With a link to a node (one item, like a frame), "the image is uploaded as a fill to that node".

Our advice: read both pages before you plan a job with pictures or brand fonts.

**A place to draft.** The tools page says `create_new_file` "Creates a new blank Figma Design, FigJam, or Figma Slides file in your drafts folder." The write page does not describe an undo step for `use_figma`. Our advice: let the agent build in a new file or a copy, and move the good parts yourself.

**Review.** The write page gives two rules:

- "Open the file in Figma and inspect the generated or updated content." Then refine it.
- "Large changes work best incrementally": the client works in smaller steps and checks each one.

### Canva: an edit is a transaction

A **transaction** is a group of changes that is saved together or not at all. The [Canva docs on start-editing-transaction](https://www.canva.dev/docs/apps/mcp/tools/start-editing-transaction/) say: "The editing flow is three tools: open a transaction, apply operations, then commit."

```text
start-editing-transaction   -> transaction_id + editable elements
perform-editing-operations  -> one status per operation (still a draft)
commit-editing-transaction  -> status "committed" = saved
```

Step by step:

1. **Open.** The tool "Returns a `transaction_id` and the design's editable elements (`richtexts` and `fills`), each with an `element_id`." It also returns `edit_design_url`, a link that opens the design in Canva.
2. **Apply.** The [Canva docs on perform-editing-operations](https://www.canva.dev/docs/apps/mcp/tools/perform-editing-operations/) give three rules. Edits stay in draft until you commit.
   - "Check `edit_operation_results` for a per-operation `status` of `success`."
   - "On responsive pages, use `find_and_replace_text` rather than `replace_text`."
   - For pictures: "Don't pass a raw image URL into an editing operation." Upload it first with `upload-asset-from-url` "to get an `asset_id`".
3. **Commit.** The [Canva docs on commit-editing-transaction](https://www.canva.dev/docs/apps/mcp/tools/commit-editing-transaction/) say: "A `status` of `committed` confirms the edits are saved." And: "If the transaction isn't committed, the edits are discarded."

**Cancel.** The [Canva docs on cancel-editing-transaction](https://www.canva.dev/docs/apps/mcp/tools/cancel-editing-transaction/) say it discards "every edit applied since start-editing-transaction". After that the draft edits "can't be recovered", and the transaction id is no longer valid.

**Two people at once.** The commit page warns: "Commit can fail if the design is edited concurrently (for example, a person editing in the browser) during your transaction. Retrying the same transaction won't help, because its snapshot is stale. Cancel it, start a fresh transaction, re-apply, and commit."

**Rights.** The [Canva access page](https://www.canva.dev/docs/apps/mcp/access/) says: "editing operations are only available on designs and assets for which you have edit permissions."

**Honest status.** The [Canva best-practice page](https://www.canva.dev/docs/apps/mcp/best-practices/) says: "Only report a saved edit after `commit-editing-transaction` returns a committed status." The [Canva handoff page](https://www.canva.dev/docs/apps/mcp/workflows/design-edit/) adds that the agent "should return a direct link to the design so the user can immediately open it in Canva".

A comparison: a Canva transaction is like a shopping basket. Nothing is yours until you pay. A Figma write is like painting on the wall: it is there at once.

### Approvals: a person says yes first

You can also stop a write in the AI app itself.

- The [Claude docs on the MCP connector](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector) (a beta feature) say: "Denylisting write or destructive tools is recommended when building read-only assistants, or when you want a human confirmation step before state changes." (A **denylist** is a block list. A tool on it cannot be called.)
- The [OpenAI docs on MCP](https://developers.openai.com/api/docs/guides/tools-connectors-mcp) say: "Use the available configurations of the `require_approval` and `allowed_tools` parameters to ensure that any sensitive actions require an approval flow."

## Worked example

The museum website from the problem. Four text elements need the new show name. The page is responsive.

### Step 1: the weak run

```text
start-editing-transaction        -> transaction_id=TX1
perform-editing-operations       4 x replace_text
commit-editing-transaction
assistant: "Updated!"
```

Three problems:

- The page is responsive, but the run used `replace_text`.
- Nobody read the four results before the commit.
- The person got a word, not a link to the design.

### Step 2: the better run

```text
start-editing-transaction        -> transaction_id=TX2, edit_design_url
perform-editing-operations       4 x find_and_replace_text
read edit_operation_results      -> 4 statuses
```

Simplified. See the docs for the exact request shape.

### Step 3: the hard case, a mixed result

**This is the hard part.** The results come back like this (our example):

```text
headline          success
section title 1   success
section title 2   (no success)
section title 3   success
```

Three of four is not done. Our reading: if you commit now, you save a page with two names for one show.

The transaction is still open, and nothing is saved yet. Our advice: look at the one element that did not succeed, send one new operation for it, and read its status again. Commit only when every result says `success`.

### Step 4: close and hand over

```text
commit-editing-transaction       -> status "committed"
assistant: "The four titles now use the new name.
            Open the page in Canva to check it: <edit_design_url>"
```

The link lets you check all four places with your own eyes.

### Step 5: why it is better

- The right operation for a responsive page.
- Every operation is checked before the commit.
- The person gets the edit link and checks the page.

## Common mistakes

1. **Using `replace_text` on a responsive page.** Canva's page names another operation for that. Fix: use `find_and_replace_text`.
2. **Editing a design you cannot edit.** The Canva docs say editing operations "are only available on designs and assets for which you have edit permissions". Fix: check the account's edit rights before you start.
3. **Giving an assistant write tools it does not need.** Fix: denylist the write tools, or set approvals, so a person says yes first.

## Try it

Not graded. Write your answer down before you read the answer.

You build a "brand checker" assistant on the Claude MCP connector. It should only read Figma files and report problems. It should never change a file. The Figma server offers `get_design_context`, `get_variable_defs`, `use_figma`, `upload_assets` and `create_new_file`.

1. Which tools do you switch off?
2. Why switch them off, if the prompt already says "only read"?

### Answer

1. **`use_figma`, `upload_assets` and `create_new_file`.** All three are write tools on Figma's list. Keep the two read tools.
2. **A prompt is a request, not a lock.** Our reading: a switched-off tool cannot be called at all. The Claude docs recommend denylisting write tools "when building read-only assistants".

## Recap

- Figma's `use_figma` writes straight into the file. It needs a Full seat plus edit permission, and its limits list (images, custom fonts, 20kb) changes, so read it before each job.
- A Canva edit is open, apply, commit. Check each operation's status, and say "saved" only after `committed`. Cancel throws the draft away for good.
- A person checks every write: approvals before, the file or edit link after.
