## Goal

After this lesson you can:

- Choose between a one-shot request and a conversation for an image job.
- Fill in a request sheet: shape, size, quality, file type, background and count.
- Plan the steps after the request: save the file, keep the rewritten prompt, count what came back.

## The problem

A bookshop wants three things for its new website:

1. Twelve small images for its book-club pages, in a few different styles.
2. A wide banner for the home page. The owner wants to tweak it with you, one comment at a time.
3. Its owl mascot as a cut-out, with no background, to sit on any page colour.

The studio intern sends one request for each job with only a prompt. Nothing else is set. The results are square, the owl sits on a white box, and nobody can find the files the next day.

The prompts were fine. The problem was everything around the prompt. A **generation API** is a model you reach with a request instead of a button. The request has more fields than the prompt, and someone has to choose them.

## The idea

### One shot or a conversation

There are two ways to ask for an image:

- **One shot.** One request, one prompt, one result. The [OpenAI docs](https://developers.openai.com/api/docs/guides/image-generation) say the Image API is the best choice when you only need one image from one prompt.
- **A conversation.** You send a request, look at the result, then send a follow-up: "same banner, warmer light". OpenAI's Responses API adds multi-turn editing for this. The [Gemini docs](https://ai.google.dev/gemini-api/docs/image-generation) recommend a multi-turn chat when you want to refine an image.

Pick by the job. Many different ideas: one-shot requests. One image that changes step by step: a conversation.

### The request is an order form

Think of a print shop. The picture is only one line on the order. You also tick the size, the paper and how many copies. An image request works the same way.

| Field      | OpenAI image models                                | Gemini image models                     |
| ---------- | -------------------------------------------------- | --------------------------------------- |
| Shape      | `size`, for example `1536x1024` (landscape)        | `aspect_ratio`, for example `16:9`      |
| Resolution | part of `size`                                     | `image_size`: `1K`, `2K` or `4K`        |
| Quality    | `low`, `medium`, `high`, `auto` (+ `xhigh`, `max`) | not a field in the guide                |
| File type  | `png` (default), `jpeg` or `webp`                  | set in `response_format`                |
| Background | transparent, opaque or `auto`                      | not a field in the guide                |
| Count      | `n` (one image if you don't set it)                | ask in the prompt, then count the files |

Six details from the docs matter most:

- **Draft cheap.** The OpenAI docs say to use the `low` quality setting "for quick drafts". For final files, they say to compare higher settings. The two newest GPT Image models add `xhigh` and `max`. Even the top setting will not make the first try perfect. It only makes each try slower and more expensive.
- **No background needs the right file type.** The OpenAI docs say to set `background: "transparent"` and use `png` or `webp`. `jpeg` is missing from it.
- **`auto` means the model picks.** For size, quality and background, the OpenAI docs say that with `auto` "the model will automatically select the best option based on the prompt". So `auto` does not promise a cut-out, and it is not the draft setting. Choose the value yourself when it matters.
- **Gemini sizes start small.** The Gemini docs say Gemini 3 image models "generate 1K images by default". For print you must ask for `2K` or `4K`. The `K` must be a capital: "Lowercase parameters (e.g., 1k) will be rejected."
- **`n` copies, it does not edit.** The OpenAI docs say `n` makes several images "in a single request". All of them come from the same prompt. It is a way to get choices, not a way to apply someone's comments.
- **Counts are a wish.** The limits list in the Gemini docs says the image models "won't always follow" the image count you ask for.

### What comes back

In an app, the image just appears. In an API, the response carries the picture as data. The OpenAI docs say the Image API returns "base64-encoded" image data. Base64 is the picture written as a long string of text. The code samples from both vendors turn that text back into a file and write it to disk. If no step does this, there is no file to deliver.

Text can come back too:

- The Gemini docs say the model "defaults to returning both text and image responses". You can ask for images only.
- In OpenAI's image tool, the main model rewrites your prompt before it makes the image. The docs say it "will automatically revise your prompt for improved performance". The new text is in a field called `revised_prompt`.

```text
your prompt --> [main model rewrites it] --> revised_prompt --> image
                                                 ^
                                  keep this next to the file
```

## Worked example

### Step 1: the weak request

The intern's request for the owl mascot:

```text
Prompt: A friendly cartoon owl reading a book, simple shapes.
```

What goes wrong:

- No background setting, so the tool may add one.
- No file type, so you get the default `png`, but only by luck.
- No size, no quality, no count, and no plan to save the file.

### Step 2: write the request sheet

```text
Job:         Owl mascot cut-out (OpenAI image model)
Prompt:      A friendly cartoon owl reading a book, simple shapes,
             centred, nothing else in the frame.
size:        1024x1024
quality:     low for 4 drafts, then high for the chosen one
background:  transparent
file type:   png
n:           4 (drafts only)
After:       save every file as owl-draft-01.png ...;
             save the revised_prompt in owl-notes.txt
```

### Step 3: the hard case

The web designer says: "Our site loads faster with `jpeg`. Make the owl a `jpeg`."

**This is the hard case.** Both wishes look small, but they clash. A transparent background needs `png` or `webp`. So the answer is `webp`: it is on OpenAI's list for transparent images, and it is a common web format. Write the reason on the sheet, so nobody "fixes" it back to `jpeg` later.

### Step 4: the other two jobs

```text
Job:         Book-club images (12, different styles)
How:         12 one-shot requests, one style each
quality:     low first; high only for the ones the owner picks

Job:         Home-page banner (Gemini 3 image model)
How:         one conversation; each owner comment is a follow-up turn
aspect_ratio: 16:9
image_size:  2K   (capital K)
```

### Step 5: why it is better

- **Every field is a choice.** Nobody gets a square banner by accident.
- **The method fits the job.** Variety comes from separate requests. Small changes come from a conversation.
- **The record is kept.** Files have names. The rewritten prompt sits next to the image, so a strange detail can be traced.
- **The count is checked.** If you asked Gemini for four images, you count the files you got, not the ones you asked for.

## Common mistakes

1. **Leaving fields to the defaults.** You get a 1K Gemini image when the job is print. Fix: fill in shape, size and quality on purpose for every job.
2. **Asking for a cut-out as `jpeg`.** The transparent background is lost. Fix: use `png` or `webp` with a transparent background.
3. **Thinking "request OK" means "file saved".** The response holds data, not a file in your folder. Fix: make "save and name the file" a step with an owner.

## Try it

Not graded. Write your answer down before you read the answer.

A teammate plans a job for a museum poster on a Gemini 3 image model:

```text
Prompt:      Night view of the museum, gold lights, poster style.
image_size:  4k
Count:       "make 6 versions" (in the prompt)
Plan:        put the 6 images straight into the print layout
```

Find two problems.

### Answer

1. **Lowercase `k`.** The Gemini docs say lowercase sizes are rejected. Write `4K`.
2. **The count is not a promise.** The model may return fewer than six images. Count the files first, then plan the layout.

A bonus point: nobody saves the files. Add a step that writes and names each image before the layout work starts.

## Recap

- Use one-shot requests for many different ideas. Use a conversation to change one image step by step.
- The request is an order form. Set shape, size, quality, file type, background and count on purpose. Draft at low quality. Transparent needs `png` or `webp`. Gemini sizes need a capital `K`.
- The response is data, not a file. Save it, keep the `revised_prompt` next to it, and count what really came back.
