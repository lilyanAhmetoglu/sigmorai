## Why it matters

A media pipeline is a chain of files. A logo goes in. An image comes out. That image goes into a video tool. A voice track comes out. Every hand-off can break: the file is the wrong type, too big, the wrong shape, or gone.

Most of these breaks are not model problems. They are file problems. You can catch them with a short check before the job starts. This lesson shows what each vendor asks for and how long it keeps your files.

## How a file gets in

There are three common ways to give a tool a file. (Bootstrap Village, chapters 3 and 4, covered what media models accept.)

| Way                 | What it is                                         | Seen at                                                             |
| ------------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| A link (URL)        | The tool downloads the file from a web address     | OpenAI file inputs, Runway inputs                                   |
| The file inline     | The file is packed as text (base64) in the request | OpenAI file inputs, Runway "data URI"                               |
| An upload and an id | You upload once, then refer to the file by id      | Claude Files API, OpenAI file ids, Gemini Files API, Runway uploads |

Why use an upload? Anthropic says the Files API gives a "create-once, use-many-times approach". You do not send the same brand kit with every request. Google says to always use its Files API when the total request is larger than 100 MB.

Each route has rules. Runway's inputs page is a good example:

- A URL must be HTTPS and use a domain name. The server must send a correct `Content-Type`. Redirects are not followed.
- Size limits differ by route. An image can be 16MB by URL but only 5MB as a data URI. Video by data URI is 16MB.
- Base64 makes a file "about 33%" bigger. To fit a 5MB data URI, the original image must be 3.3MB or less.

Example: a 4MB product photo sent inline to Runway is over the 5MB limit once base64 has made it bigger. The same photo sent by URL, or as an upload, is under the limit.

One privacy note from Anthropic: uploaded files are "accessible to your entire workspace, not scoped to an end user, conversation, or session". Do not put files for two clients in one workspace if they must stay apart.

## Shape: files get cropped

Runway's primer warns that inputs "are auto-cropped to the target aspect ratio when they do not match, which can silently change your composition". Example: you give a square product photo to a 9:16 video job. The tool crops it. The label on the bottle may be cut off. Match the shape first.

## How a file comes out

Outputs arrive in different ways:

- **OpenAI images:** the Image API "returns base64-encoded image data". The default is `png`. You can ask for `jpeg` or `webp`. For a transparent background use `png` or `webp`.
- **OpenAI speech:** the default is `mp3`. Other formats are `opus`, `aac`, `flac`, `wav` and `pcm`. The docs say `pcm` holds raw samples "without the header". Raw PCM has no header. Google's own sample adds a WAV header before saving, so a raw file may need the same before an editor opens it.
- **Gemini speech:** the guide's sample saves the default WAV output (`audio/wav`).
- **Runway:** the task result holds links to the output. These links are temporary.

Pick the file type for the next step. A web banner may want `webp`. A video editor may want `wav` audio. A logo with no background needs `png` or `webp`.

## How long files are kept

This part surprises teams the most.

| Where                    | How long                                                                   |
| ------------------------ | -------------------------------------------------------------------------- |
| Runway output links      | "expire within 24-48 hours"; "do not expose them directly in your product" |
| Veo videos               | stored 2 days, then removed (Bootstrap Village, chapter 4)                 |
| Gemini Files API uploads | stored 48 hours; you "can't download user-uploaded files"                  |

Anthropic's Files API is different. Anthropic says uploaded files "persist until you delete them", or until an expiry time you set at upload. Check that against your client's data rules.

Example: a Veo clip is made on Friday evening. Nobody downloads it. On Monday morning it is gone, and you must generate it again.

## A hand-off check

This is our checklist, not a vendor rule. Before each step in a chain, ask:

1. **Type.** Is the file type one the next tool accepts?
2. **Size.** Is it under the limit for how I send it?
3. **Shape.** Does its aspect ratio match the next job?
4. **Place.** Where is it saved, and by whom?
5. **Time.** When will the vendor delete it?

## What this means for your work

- **Save results the same day.** Move files into your own storage and name them.
- **Never share a temporary link as a deliverable.** It expires.
- **Match shape and type before you submit.** Fix it in the file, not in the tool.
- **Know where client files live.** Uploads can be visible to a whole workspace.
