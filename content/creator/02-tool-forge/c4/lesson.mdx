## Goal

After this lesson you can:

- Pick how a file goes into a tool (link, inline or upload) and check it against the size limit for that route.
- Choose an output file type that the next step can open, for example an audio file a video editor accepts.
- Say how long each vendor keeps a file, and who else can see it.

## The problem

A bakery wants a 9:16 story video for its new cake. The plan has four steps:

1. Two cake photos go into a Runway video job. Both are square. One is 3.6 MB, one is 4.1 MB. The team sends them inline in the request, because "5 MB is the limit".
2. A voice-over is made with OpenAI speech as `pcm`, then handed to a video editor.
3. A Veo clip of the shop front is made on Wednesday. The editor plans to download it on Saturday.
4. The finished Runway link goes into a message to the bakery owner.

Every step looks fine. Three of them will break. None of these breaks is a model problem. They are file problems: the wrong size, the wrong shape, the wrong type, or a file that is gone.

## The idea

A media pipeline is a chain of hand-offs. Think of a relay race: the runners can be fast, but a dropped baton loses the race. Each hand-off has five things to check.

```text
TYPE   can the next tool open this file type?
SIZE   is it under the limit for the way I send it?
SHAPE  does the aspect ratio match the next job?
PLACE  where is it saved, and who can see it?
TIME   when will the vendor delete it?
```

This checklist is ours, not a vendor rule. The facts behind each line come from the docs.

### Three ways in

A tool can get a file in three ways:

| Way                 | What happens                                      | Examples                                             |
| ------------------- | ------------------------------------------------- | ---------------------------------------------------- |
| A link (URL)        | the tool downloads the file from a web address    | OpenAI `file_url`, Runway URL inputs                 |
| Inline (base64)     | the file is written as text inside the request    | OpenAI `file_data`, Runway data URI                  |
| An upload and an id | you upload once, then point to the file by its id | Claude Files API, OpenAI `file_id`, Gemini Files API |

The [OpenAI file inputs docs](https://developers.openai.com/api/docs/guides/file-inputs) list all three. The [Claude Files API docs](https://platform.claude.com/docs/en/build-with-claude/files) call uploads a "create-once, use-many-times approach": you do not send the same brand kit with every request. The [Gemini Files API docs](https://ai.google.dev/gemini-api/docs/files) say to "Always use the Files API" when the whole request is larger than 100 MB.

### Size depends on the route

The [Runway inputs page](https://docs.dev.runwayml.com/assets/inputs) gives different limits per route:

| Input | By URL | By data URI |
| ----- | ------ | ----------- |
| Image | 16MB   | 5MB         |
| Video | 32MB   | 16MB        |
| Audio | 32MB   | 16MB        |

The trap is base64. The data URI limit is for the **encoded** text, and the page says encoding "increases its size by about 33%". So a 5MB data URI fits an image file of only "3.3MB or less". For bigger files, the page says to "upload assets to object storage instead".

URLs have rules too. The Runway page says: "All URLs must be HTTPS." And: "Redirects are not followed." A link that sends you on to another link counts as a failed request.

### Shape: the tool crops for you

The [Runway primer](https://docs.dev.runwayml.com/ai-context.md) warns that inputs "are auto-cropped to the target aspect ratio when they do not match, which can silently change your composition". It does not stretch the picture and it does not add bars. It cuts. A square photo in a tall video loses its sides. Make the right shape yourself first, so you choose what stays in the frame.

### Type: pick the format the next step needs

The output format decides who can open the file.

- **OpenAI images.** The [image docs](https://developers.openai.com/api/docs/guides/image-generation) say the Image API returns "base64-encoded image data". The default is `png`; you can ask for `jpeg` or `webp`. Your code still has to save it as a file.
- **OpenAI speech.** The [text-to-speech docs](https://developers.openai.com/api/docs/guides/text-to-speech) list the formats below.
- **Gemini speech.** The [speech docs](https://ai.google.dev/gemini-api/docs/speech-generation) show a sample that saves "the default WAV output audio".

| OpenAI speech format | What the docs say                                            |
| -------------------- | ------------------------------------------------------------ |
| `mp3`                | "The default response format for general use cases."         |
| `flac`               | "For lossless audio compression"                             |
| `wav`                | "Uncompressed WAV audio"                                     |
| `pcm`                | "Similar to WAV but contains the raw samples" with no header |

The header is the short label at the start of an audio file. It tells a player how to read the sound. A raw file with no header is like a book with no cover and no page numbers: the words are there, but many apps cannot open it.

### Time and place: who keeps the file, and for how long

| Where                    | How long                                                                         |
| ------------------------ | -------------------------------------------------------------------------------- |
| Runway output links      | "they will expire within 24-48 hours"                                            |
| Veo videos               | "stored on the server for 2 days, after which they are removed"                  |
| Gemini Files API uploads | "Files are stored for 48 hours", and "you can't download user-uploaded files"    |
| Claude Files API uploads | "Files persist until you delete them"; you can also set an expiry time at upload |

The [Runway outputs page](https://docs.dev.runwayml.com/assets/outputs) asks you to "download the data" and save it to your own storage, and says: "do not expose them directly in your product." The [Veo docs](https://ai.google.dev/gemini-api/docs/veo) say you "must download your video within 2 days of generation".

The Claude Files API has a privacy point. Its docs warn that uploads are "accessible to your entire workspace, not scoped to an end user, conversation, or session". Any API key for that workspace can use them. For apps with many customers, the docs say to "create a separate workspace for each tenant". For a studio, a tenant is a client.

## Worked example

### Step 1: the weak plan

```text
1  cake-a.png 3.6 MB, cake-b.png 4.1 MB, both 1:1
   -> sent inline (data URI) to a 9:16 Runway job
2  voice-over: OpenAI speech, response_format pcm -> video editor
3  Veo shop-front clip, made Wednesday, download Saturday
4  Runway output link -> message to the bakery owner
```

### Step 2: run the five checks on each step

```text
Step 1  SIZE   cake-a: 3.6 x 1.33 = about 4.8 MB encoded. Fits.
               cake-b: 4.1 x 1.33 = about 5.5 MB encoded. Over 5MB.
        SHAPE  1:1 into 9:16. The tool will crop the sides.
Step 2  TYPE   pcm has no header. The editor may not open it.
Step 3  TIME   Veo keeps the clip 2 days. Saturday is too late.
Step 4  TIME   the link expires in 24-48 hours. PLACE: our storage.
```

### Step 3: the hard case

**The hard case is the two photos.** Both are under 5 MB on disk, so both "look" fine. But the limit counts the base64 text, not the file on disk. Cake-a just fits. Cake-b does not. A rule like "under 5 MB is OK" passes one and fails the other, and nobody knows why.

The safe fix is one rule for both: send big images by HTTPS URL (16MB limit) or as an upload. Then the 33% does not matter. If you must send inline, check the file is 3.3MB or less.

### Step 4: the good plan

```text
1  cake-a, cake-b: crop to 9:16 by hand, keep the cake centred.
   Upload to our storage, send by HTTPS URL (no redirect).
2  voice-over: response_format wav -> video editor
3  Veo clip: download the same day it is made; name it shopfront-v1.mp4
4  download the Runway video, save it in /bakery/final/,
   send the owner our own copy, not the Runway link
```

### Step 5: why it is better

- **Size uses the right number.** It checks the encoded size, or skips the problem with a URL.
- **Shape is chosen, not cropped by chance.** The cake stays in the frame.
- **The type fits the next tool.** `wav` carries a header, so the editor can read it.
- **Files are saved before they vanish.** The client gets a file that does not expire.

## Common mistakes

1. **Reading the data URI limit as the file size.** Base64 adds about 33%. Fix: keep inline images at 3.3MB or less, or send a URL or an upload.
2. **Sending a vendor's output link as the deliverable.** It expires. Fix: download the file the same day and share your own copy.
3. **One shared workspace for every client.** Any key in it can use every file. Fix: one workspace per client for confidential files.

## Try it

Not graded. Write your answer down before you read the answer.

A teammate plans this for a yoga studio:

```text
- Logo, 2.9 MB PNG, sent inline (data URI) to a Runway image job
- Class photo, 4:3, used in a 16:9 Runway video
- Brand guide uploaded to the Gemini Files API on Monday,
  to download again next week
```

Which lines are fine, and which will cause trouble?

### Answer

1. **Logo: fine.** 2.9 MB is under 3.3MB, so the encoded file stays under the 5MB data URI limit.
2. **Class photo: trouble.** It will be auto-cropped to 16:9, and people at the top or bottom may be cut. Crop it yourself first.
3. **Brand guide: trouble twice.** Gemini keeps uploads for 48 hours, and you cannot download a file you uploaded. Keep the master copy in your own storage.

## Recap

- Each route has its own size limit. A data URI limit counts the base64 text, which is about 33% bigger than the file.
- Match the shape before the job, or the tool crops it. Pick the output type the next step can open: `wav` has a header, `pcm` does not.
- Vendor files and links expire (Runway links in 24-48 hours, Veo videos after 2 days, Gemini uploads after 48 hours). Save your own copy, and keep each client's files in its own workspace.
