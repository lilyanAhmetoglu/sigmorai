## Goal

After this lesson you can:

- Say what a seed is, what it repeats, and what breaks a repeat.
- Save everything you need to make an image again, on an API or on your own GPU (graphics card).
- Explain what steps and guidance trade, and which models let you change them.

## The problem

Leafline is an online plant shop. In March, the team made 40 product backgrounds with the Ideogram 4.5 API. They saved each image and the prompt they typed.

In October, the print shop asks for one background again: the team's copy was a small web version, and the print needs a fresh, full-size run. The team sends the same prompt again. The new image is close in mood, but the shelf, the light and the pot are all different.

The team did not change the prompt. So what changed? The answer is in the parts nobody saved.

## The idea

### Why the same prompt gives a new picture

The [diffusers docs](https://huggingface.co/docs/diffusers/en/using-diffusers/reusing_seeds) (diffusers is Hugging Face's library for running image models yourself) say: "Diffusion is a random process that generates a different output every time."

A diffusion model starts from random noise and cleans it up, step by step, until a picture appears (our plain summary). The noise is new each run, so the picture is new each run.

A **seed** is the number that sets the starting noise. The [Ideogram settings page](https://docs.ideogram.ai/create/image-settings) says: "The seed is the number a run starts from."

A comparison: a seed is like the page number in a book of random noise. Same page, same start.

### What a seed repeats

The Ideogram settings page gives a rule with four parts. Keep the prompt, the model, the settings and the seed all unchanged. Then you get "the same or a very close result". It adds: "Change one word and keep the seed to try a small change while keeping most of the layout."

And the limit, in a warning box: "Switching models, or changing a key idea in the prompt (say, "photo" to "painting"), gives a different image even with the same seed."

In the Image app, every model has a **Seed** field, in its **Advanced settings**. When the field is empty it shows "Random", "which means each run gets a new seed."

### Seeds on the Ideogram API

The [Ideogram 4.5 API page](https://developer.ideogram.ai/api-reference/images/generate/ideogram-4-5) lists a `seed` field: "Set for reproducible generation." Each image in the response comes back with:

- `seed`: the seed it used. The page marks it required, so it is always there.
- `prompt`: "The final prompt the image was generated from."
- `resolution`: the size it was made at.

Why a "final" prompt? Because of `magic_prompt`. The page says `auto` "(the default) and `on` rewrite and expand the prompt before generation." The value `off` "keeps your wording and only converts it into a structured prompt." It also says: "A valid structured JSON prompt skips magic prompt unless `magic_prompt` is `on`." (A JSON prompt is a prompt written as named fields.)

The `size` field matters too: "auto" or no size "picks a supported size based on the prompt."

### Seeds on your own GPU

The diffusers docs explain seeds in code. You pass a `Generator`, set with `manual_seed`. Three rules:

- "Use a CPU `Generator` when you care about reproducibility. CPU RNG is more stable across machines." (RNG means random number generator.) A GPU one "can diverge from CPU results."
- A `Generator` "keeps a random state that is consumed and updated when you use it." So: "Reseed it or create a new `Generator` before each call when you need the same seed again."
- It is still not a promise: randomness can be limited, "but it is not _guaranteed_ even with an identical seed."

Our reading: a seed means near enough, not the very same pixels.

### Where there is no seed

- **FLUX 3 Image.** The [BFL page](https://docs.bfl.ai/flux_3/flux3_image_generate) says the endpoint "rejects unknown fields with HTTP `422`, so fields from other BFL endpoints, such as `seed`, `width`, and `input_image`, don't work here." HTTP 422 is an error reply: the request is refused.
- **OpenAI and Gemini.** Neither image guide lists a seed for repeating an image (our check of both pages, October 2026). Google's [API reference](https://ai.google.dev/api/generate-content) has a general setting: "Seed used in decoding." But the image guide does not say it repeats an image, so don't count on it for that (our reading).

These guides offer other ways to keep a picture steady. The [Gemini docs](https://ai.google.dev/gemini-api/docs/image-generation): "Multi-turn conversation is the recommended way to iterate on images." The [OpenAI docs](https://developers.openai.com/api/docs/guides/image-generation) let you carry an image forward in a conversation with `previous_response_id`. Our advice: on these two, save the approved file and keep editing it.

### Models that move

The [FLUX.2 overview](https://docs.bfl.ai/flux_2/flux2_overview) says: "Preview endpoints are where our latest improvements land first." It also lists fixed ones. `flux-2-pro` is "A fixed snapshot of FLUX.2 [pro]. This endpoint will not change, making it suitable for workflows that require reproducibility." A **snapshot** is a saved copy of a model that does not change (our gloss). Our reading: a seed can't repeat a picture if the model under it has changed.

### Steps and guidance

Two more knobs appear on some models. The [diffusers FLUX.2 page](https://huggingface.co/docs/diffusers/en/api/pipelines/flux2) explains both.

- **Steps** (`num_inference_steps`) are the clean-up rounds. In `Flux2Pipeline` the default is 50; the [klein] KV pipeline on the same page defaults to 4. "More denoising steps usually lead to a higher quality image at the expense of slower inference."
- **Guidance** (`guidance_scale`) is how hard the model follows your prompt. "Higher `guidance_scale` encourages a model to generate images more aligned with `prompt` at the expense of lower image quality."

The same page has a prompt rewrite of its own, "caption upsampling". It runs when you set `caption_upsample_temperature`.

Which FLUX.2 models let you change steps and guidance? The BFL overview table lists "Adjustable steps & guidance" for FLUX.2 [flex]. Most others say "Standard". FLUX.2 [klein] is "step-distilled": trained to work in only 4 inference steps (our gloss of the table).

## Worked example

Our example. Every name and number in it is invented.

### Step 1: the weak record

What the team saved in March:

```text
file:    fern-shelf-web.jpg   (a small web copy)
prompt:  "A potted fern on a light oak shelf, soft morning light"
```

There is no seed. There is no record of `magic_prompt`, `size` or `quality`. So the October run started from new noise and a new rewrite.

### Step 2: what the API had already sent back

The March response held everything. It was just never stored:

```text
seed:        58213
resolution:  1024x1024
prompt:      (final) a longer text: the fern, the shelf, plus details
             the rewrite added, such as a linen curtain and a white pot
```

### Step 3: the hard case

**The hard case is the final prompt.** `magic_prompt` was on `auto`, the default, so the API sent back a longer final prompt than the one typed. Sending the typed prompt again asks for a fresh rewrite.

Our reading of the API page: send the saved final prompt, with the same seed, size and quality, and `magic_prompt` set to `off`. The page says `off` "keeps your wording and only converts it into a structured prompt".

```text
model:         Ideogram 4.5
prompt:        <the saved final prompt, word for word>
magic_prompt:  off
seed:          58213
size:          1024x1024     (not "auto")
quality:       high
```

### Step 4: the good record, from now on

```text
image:         fern-shelf-0007.png    (the full-size file, not only a web copy)
model:         Ideogram 4.5
typed prompt:  "A potted fern on a light oak shelf, soft morning light"
final prompt:  <from the response>
magic_prompt:  auto
seed:          58213
size:          1024x1024
quality:       high
date:          2026-03-14
```

### Step 5: why it is better

- **The final prompt is stored.** The record holds the words the API really used.
- **Nothing is left on "auto".** Size and quality are written down.
- **The master file is kept.** The best repeat is the original file itself.

## Common mistakes

1. **Changing steps and guidance in the same test.** You can't tell which one helped. Fix: change one knob at a time and compare side by side.
2. **Saving only a web copy.** A small copy can't go to print. Fix: keep the full-size master file with the record.
3. **Tuning steps on BFL's API when the model doesn't offer it.** The BFL overview table gives [klein] "Standard" controls; only [flex] lists "Adjustable steps & guidance". Fix: check the model table before you plan a tuning test.

## Try it

Not graded. Write your answer down before you read the answer.

A teammate runs three jobs. For each, say what the run may change on its own, and what to save.

1. On the Ideogram 4.5 API: a valid structured JSON prompt, with `magic_prompt` on `auto`.
2. On the Ideogram 4.5 API: a request with no `size` field.
3. On diffusers FLUX.2: `caption_upsample_temperature=0.15` is set.

### Answer

1. **Nothing is rewritten.** The API page says: "A valid structured JSON prompt skips magic prompt unless `magic_prompt` is `on`." Save the JSON exactly as sent.
2. **The size.** With no size, the API "picks a supported size based on the prompt". Save the `resolution` from the response.
3. **The prompt.** With this value set, the pipeline tries caption upsampling first. Save the value, and the rewritten prompt if you can see it (our advice).

## Recap

- A seed sets the starting noise. With nothing else changed, it repeats an image closely. A new model or a new key idea gives a new image.
- Save the seed with the words it was used with: the final prompt after any rewrite. Leave nothing on "auto", and keep the master file.
- Steps trade time for quality; guidance trades quality for prompt-following. Some models let you change them, some don't, and some APIs have no seed at all.
