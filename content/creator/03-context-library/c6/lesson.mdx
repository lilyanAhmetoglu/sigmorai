## Why it matters

Every asset in a library came from somewhere. A client sent it. A stock site licensed it. A freelancer drew it. The studio's own model made it. Someone found it online. Before an asset goes into a reference set, someone must know which of these it is, and what it may be used for.

**This is not legal advice.** This lesson is about records. It shows what vendor docs say and what a studio can keep on file. Laws differ by country. For a contract or a legal question, ask a lawyer or your producer.

Realm 0, chapter 6 covered vendor usage policies and provenance labels. This lesson turns them into a library habit.

## A rights record

A **rights record** is a short note kept with each asset. It is our method. A reference card (chapter 2) says how an image is used. A rights record says whether you may use it.

| Field        | Example                                                |
| ------------ | ------------------------------------------------------ |
| Source       | Client packshot, sent by email on 3 March              |
| Who owns it  | The client, or the stock site, or the freelancer       |
| Allowed use  | Campaign images, as a reference for AI work: yes or no |
| Valid until  | 31 December 2027                                       |
| People shown | Names, and where the written permission is             |
| Made by AI   | Which model, which date, which prompt log              |
| Proof        | Where the contract or email is stored                  |

If a field is empty, the asset does not go into a set until someone fills it.

## The vendors put the duty on you

Two vendors say it in their docs.

- **Google**, before its image editing examples: "Make sure you have the necessary rights to any images you upload."
- **Runway**, for talent references: "only use references of people you have permission to depict". It adds: "You are responsible for the rights to any likeness you submit."

These are reminders, not checks. The docs do not say that a tool will find out for you. So the record is yours to keep.

## Keep the record outside the file

A file can carry a label of where it came from. OpenAI's provenance page says C2PA metadata "provides more context about a file's origin". It also says: "Editing, converting, or sharing a file can remove its metadata." The C2PA site describes Content Credentials as a way to show "the origin and edits of digital content".

So do not make the file the only place you note its source. A designer resizes a packshot and the label is gone. Our habits:

- **Keep the original file untouched** in an archive, with any credentials it came with.
- **Write the source in the catalogue**, where an edit cannot remove it.

## AI-made assets need a record too

Google's docs say all images from its Nano Banana models include a SynthID watermark. A watermark can mark an image as AI-made. In our reading, it does not record your prompt, the model version or the reference images that went in.

The inputs of AI work can matter. If an image was made from a licensed stock photo, the terms of that licence may still apply. Ask your producer or a lawyer. The record for an AI-made asset lists the model, the date, the prompt log and every reference used. This is our rule.

## Make rights searchable

In chapter 3, filters hold the hard rules. Rights are hard rules. OpenAI lets you set `attributes` on a vector store file. Google lets you add custom metadata to a file. Store fields such as `valid_until` and `reference_ok` there. Then search can filter out an expired or blocked asset before the model sees it.

## When a licence ends

Copies of your assets may sit with vendors. Chapter 4 of realm 2 covered how long each vendor keeps files. Here the question is how to remove them.

- **Anthropic:** files "persist until you delete them" or until their `expires_at`. You can set `expires_in_seconds` when you upload. It must be between 3,600 (1 hour) and 7,776,000 (90 days), and it is set once. Anthropic says expiration "is a lifecycle feature, not a guaranteed-deletion control". To remove a file earlier, use `DELETE`. Deleted files cannot be recovered.
- **OpenAI:** its data controls table lists application state for `/v1/files` as "Until deleted". Files can be deleted by hand, or automatically with `expires_after`. A vector store also has `expires_after`. When it expires, its vector store file objects are deleted. The same table lists 30 days of abuse monitoring retention for `/v1/files`.

A licence that lasts a year is longer than Anthropic's 90-day maximum. So put the end date in the catalogue, and add a step to delete the vendor copies on or before that date. Then mark the asset retired.

## What this means for your work

- **A record for every asset.** Source, owner, allowed use, end date, people, AI origin, proof.
- **Empty field, no entry.** The asset stays out of sets until it is filled.
- **Keep the original.** Labels in files can disappear. The catalogue lasts.
- **Record the inputs of AI work.** Model, date, prompt log and references.
- **Filter on rights.** Store dates and flags where search can use them.
- **Delete on the end date.** Do not rely on expiry alone.
