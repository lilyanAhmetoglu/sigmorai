## Goal

After this lesson you can:

- Cut long audio and video so each piece fits the vendor's size, length and detail limits.
- Catch fast moments the model may miss, and ask for exact points in time.
- Lay out a long transcript in a prompt, and check every timestamp by hand.

## The problem

A music festival sends a studio two long files for its archive:

- `panel-talk.mp3`: a 2-hour panel with four speakers, 140 MB.
- `festival-recap.mp4`: a 150-minute film. The text on the stage banners must be readable.

The studio sends both files as they are. Three things go wrong. The audio upload is refused because it is too big. The film summary skips a 1-second firework burst. And the model says "the drummer's solo starts at 63:10", but at that time the screen shows the crowd.

A model cannot simply "watch everything". Long media has three problems: **size** (will it fit?), **detail** (what does the model miss?) and **finding** (where is the moment?).

## The idea

**Turn speech into text first.** A transcript is easy to search and to read with any text model.

- The [OpenAI docs](https://developers.openai.com/api/docs/guides/speech-to-text) say: "Request the `diarized_json` response format to receive segments with `speaker`, `start`, and `end` metadata." For audio longer than 30 seconds, also set `chunking_strategy`. This uses a special speaker-label model, and the docs note that it "doesn't support prompts".
- The [Gemini audio docs](https://ai.google.dev/gemini-api/docs/audio) show a prompt that asks for timestamps for each segment "(Format: MM:SS)". The max length is "9.5 hours of audio per prompt".

**Size: cut at pauses.** The OpenAI docs set a file limit and a way to split:

- "The Transcriptions API accepts files up to 25 MB."
- "For larger recordings, use a compressed audio format or split the file into chunks of 25 MB or less."
- "Avoid splitting in the middle of a sentence, which can remove context and reduce accuracy."

So the file is not split for you. An exact cut every 25 MB can land mid-sentence. A bigger, uncompressed format goes the wrong way.

**Video: one frame per second by default.** The [Gemini video docs](https://ai.google.dev/gemini-api/docs/video-understanding) say the model samples video "at a rate of **1 frame per second** (FPS)". This "works well for most content", but "it may miss details in videos with rapid motion or quick scene changes". It is like a security camera that takes one photo each second: a fast thing can happen between two photos.

You can change this in two ways:

- Set an `fps` value. The docs' example is `0.5`: "Sample 1 frame every 2 seconds". A higher value reads more frames.
- Clip the video with `start_offset` and `end_offset`.

The docs say these options "are only supported when processing the video in `"static"` mode".

**Length and detail trade.** The Gemini video docs say: "Models with a 1M context window can process videos up to 3 hours long by default (at low media resolution), or up to 1 hour long at high media resolution." More frames do not raise this limit. If you need fine detail, send shorter parts.

```text
low media resolution   up to 3 hours   less detail
high media resolution  up to 1 hour    more detail
```

**Static or agentic.** Static mode "Extracts frames at a fixed rate (1 FPS)". In agentic mode, "The model dynamically navigates the video timeline, loading only the content it needs". The docs say: "start with **agentic** mode". Static fits "short clips (under 5 minutes)" or frame-level precision. Only some Gemini models support agentic mode, so check the table.

**Large files go through the Files API.** The Gemini video docs say: "Always use the Files API when the total request size (including the file, text prompt, system instructions, etc.) is larger than 20 MB, the video duration is significant, or if you intend to use the same video in multiple prompts."

**Ask for time.** The Gemini video docs say you can ask about points in a video "using timestamps of the form `MM:SS`". A timestamp is a pointer, not a proof. Our habit: open the file at that time, look or listen, then use it.

**Long text: documents first, question last.** The [Claude prompting docs](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) give advice for "large documents or data-rich inputs (20k+ tokens)":

- "Put longform data at the top": above "your query, instructions, and examples".
- With several documents, wrap each in `<document>` tags with a `<source>`.
- "Ground responses in quotes": ask the model to quote the relevant parts first, then do the task.

## Worked example

### Step 1: the plan before

```text
panel-talk.mp3       140 MB, send as one file
festival-recap.mp4   150 min, one request, high media resolution
Question             "Summarise the panel. When is the drum solo?"
```

What goes wrong:

- 140 MB is over the 25 MB limit.
- 150 minutes is over the 1-hour limit for high media resolution.
- The answer has no quotes, and the time is never checked.

### Step 2: cut the audio

140 MB ÷ 25 MB = 5.6, so at least 6 chunks. Cut each one at a pause between speakers, near 23 MB, so no chunk is over 25 MB and no sentence is cut in half. Ask for `diarized_json` with `chunking_strategy` set, so each line has a speaker and a start and end time.

### Step 3: cut the film

The banner text needs high media resolution, so each part must be 1 hour or less. Three parts of 50 minutes fit. Upload them with the Files API.

### Step 4: the hard case, the 1-second firework

The firework lasts about one second, near 47:20, between two sampled frames. A higher `fps` for the whole film adds a lot to read. Instead, clip only that stretch in static mode and raise the rate:

```text
start_offset:  2830   (47:10)
end_offset:    2860   (47:40)
fps:           5
```

Simplified. See the docs for the exact request shape.

Now the model reads about 150 frames for those 30 seconds, not 30.

### Step 5: lay out the transcript

The transcript is about 60,000 tokens. For a Claude model, put it first and the question last:

```text
<document>
  <source>panel-talk, chunks 1-6</source>
  <document_content>[the full transcript]</document_content>
</document>

Quote every line where a speaker talks about ticket prices.
Then list the three clearest quotes for a social post.
```

### Step 6: check, then log the moment

The model says the drum solo starts at 63:10. A person opens the film at 63:10. The solo really starts at 63:42. The checked time goes into a **moment sheet** (our method): one row per moment.

```text
Asset:   festival-recap.mp4
In, out: 63:42 to 64:30
What:    drum solo, main stage
Who:     band name, as cleared in the rights record
Check:   opened and confirmed by a person, 12 June
```

### Why it is better

- **Every piece fits a limit**: 25 MB for audio, 1 hour for high-detail video.
- **The fast moment is caught** by a clip with a higher frame rate.
- **The long text comes first**, and the answer is built from quotes.
- **Every time is checked** in the file first.

## Common mistakes

1. **Exact cuts by size.** A cut every 25 MB can split a sentence. Fix: cut at pauses, under the limit.
2. **Trusting the sample rate.** At 1 frame per second, short events can fall between frames. Fix: clip the stretch and raise `fps`.
3. **Asking the model twice instead of checking.** The same time twice is still unchecked. Fix: open the file at that time.

## Try it

Not graded. Write your answer down before you read the answer.

A museum has a 100-minute tour video. Visitors must be able to read the small labels next to the paintings. The model is Gemini, with a 1M-token context window. How do you send it, and why not in one request?

### Answer

- **Two parts of 50 minutes, each at high media resolution.** Small labels need fine detail.
- **Not one request at high resolution:** 100 minutes is over the 1-hour limit at high media resolution.
- **Not one request at low resolution:** it fits the 3-hour limit, but the labels may not be readable.
- Upload both parts with the Files API. The Gemini video docs say to use it when the request is over 20 MB or the video is long.

## Recap

- Text first for speech: a transcript with speakers and times. Keep audio chunks at 25 MB or less, cut at pauses.
- Video is sampled at 1 frame per second by default. For fine detail, use high media resolution and parts of 1 hour or less. For a fast moment, clip it and raise `fps`.
- Put long documents before the question and ask for quotes. Check every timestamp in the file before it goes on the moment sheet.
