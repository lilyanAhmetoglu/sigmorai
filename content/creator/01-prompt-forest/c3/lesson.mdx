## Goal

After this lesson you can:

- Write a **style block**: a fixed text that describes the look, separate from the subject.
- Keep style words out of the subject lines, so the block stays in charge.
- Use a vision model to draft the block, check its draft, and catch drift with an anchor image.

## The problem

Leo makes a small fantasy game. He needs 20 inventory icons: a sword, a key, a potion, a map and so on. In the game they sit side by side in one grid, so they must look like one set.

Leo writes each prompt on its own. The sword comes back as a glossy 3D render. The key is a watercolour. The potion is a flat cartoon with thick lines. Each icon is fine alone. Together they look like three games.

The cause: each prompt describes the look in new words, or not at all. The model fills every gap in a new way.

## The idea

Split every prompt into two parts. The **subject** changes from icon to icon. The **style** stays the same. Think of a uniform: every player's name is different, but the shirt is the same.

The [Gemini docs](https://ai.google.dev/gemini-api/docs/image-generation) show this split in their template for stylized images: "A [style] of a [subject...] doing [activity]. The design features [visual qualities...] and [color/background preference]." They add: "Be specific about the visual detail (bold lines, colors, etc.) for consistent results."

A **style block** is our own method, built from that template. It is a short text that describes only the look. You put the same block in every prompt and change only the subject line.

```text
[style block v1]  same text in every prompt
[subject line]    the only part that changes
```

What goes in a style block:

- **Medium:** flat vector, pixel art, studio photo, 3D render.
- **Line and shape:** bold outlines, soft edges, chunky shapes.
- **Colour:** named colours, and the background.
- **Light:** where it comes from, hard or soft.
- **Rules in positive words:** "plain dark-slate background", not "no busy background".

**Pictures can help.** Vision models from Anthropic, OpenAI and Google can read images and answer in text. The [OpenAI vision docs](https://developers.openai.com/api/docs/guides/images-vision) say you can ask about "objects, shapes, colors, or textures". The [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision) say Claude can analyze several images in one request "jointly". So a vision model can draft your block from existing art. But check the draft. The Claude docs warn that errors are more likely with "low-quality, rotated, or very small images under 200 pixels". The [Gemini docs](https://ai.google.dev/gemini-api/docs/image-understanding) say to use clear images.

**Consistency is not promised.** The [OpenAI image docs](https://developers.openai.com/api/docs/guides/image-generation) list visual consistency over many generations as a limit. Two habits help:

- Keep one approved image as an **anchor** and compare every new image with it (our habit).
- Reuse earlier images. For a character from many angles, Google says to "include previously generated images in subsequent prompts to maintain consistency".

The [Claude prompting docs](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) say a few good examples "improve accuracy and consistency". That is about text prompts, but the idea carries over: approved images are your examples.

## Worked example

### Step 1: the weak prompts

```text
A cool sword icon.
A key icon, magical watercolour feel.
A potion bottle, cartoon style, fun.
```

What goes wrong:

- Each line describes a different look, or none.
- Style words ("watercolour", "cartoon") are mixed into the subject.

### Step 2: draft the block with a vision model

Leo has three old icons he likes. Each file is 48 px wide. He sends them to a vision model and asks for the shared look. The draft says: "soft watercolour washes, no outlines".

Leo can see the icons have hard black outlines and flat colour. The draft is wrong. Why? The icons are tiny, under 200 pixels, which is where the Claude docs warn about mistakes. Leo exports the icons again from his source files at 512 px, sends them, then edits the new draft by hand.

### Step 3: freeze the block

```text
Style block v1:
Flat vector game icon, centred, filling most of the frame.
Bold black outlines of even width, flat colour fills, one small
white highlight on the top-left of each object.
Palette: dark slate background, warm gold, deep teal, brick red.
Plain dark-slate square background. Square 1:1.
```

Each prompt is then the block plus one line:

```text
[style block v1]
Subject: a short steel sword with a leather-wrapped handle.
```

### Step 4: test before you make all 20

Run the block with three very different subjects: a sword, a rolled map, a round potion. Put the results side by side. Do the outlines, colours and light match? If one is off, fix the block, call it v2, and test again.

### Step 5: the hard case, style words in the subject line

Icon 14 comes back glossy and realistic. Its subject line:

```text
Subject: a realistic, shiny golden crown with photographic detail.
```

"Realistic", "shiny" and "photographic" are style words. They fight the block, and here they won. Fix the subject line so it names only the object:

```text
Subject: a golden crown with five points and three red gems.
```

**Why this is the hard case:** the block is fine, so it is easy to blame the model. The leak is in the line you change every time.

### Step 6: review against the anchor

The approved sword is the anchor. Put each new icon next to it. Check outline width, palette and the highlight. Fix any icon that drifts before it goes into the game.

### Why it is better

- **One look, written once.** The style words are identical in all 20 prompts.
- **Subject lines carry only objects**, so they can't pull the style.
- **The vision draft is checked**, with large, clear files.
- **Every icon is compared** with one anchor.

## Common mistakes

1. **New style words in every prompt.** Each rewording is a new look. Fix: copy the same block, word for word, and version it (v1, v2).
2. **Style words in the subject line.** "Realistic", "watercolour" or "3D" in the subject can override the block. Fix: the subject line names only the object and its parts.
3. **Trusting a vision draft of tiny images.** Small, blurry or rotated files cause wrong readings. Fix: send larger, clear files, and correct the draft yourself.

## Try it

Not graded. Write your answer down before you read the answer.

A candle shop wants 10 product illustrations. Here is the prompt for candle 3:

```text
Flat illustration, thin brown outlines, cream background, sage and
amber colours. Subject: a tall pillar candle in a glossy, photorealistic
glass jar with dramatic cinematic lighting.
```

1. Which words in the subject line break the style?
2. Rewrite the subject line.

### Answer

1. "glossy", "photorealistic" and "dramatic cinematic lighting". They describe a look, not the object. They fight "flat illustration".
2. For example: "Subject: a tall pillar candle in a clear glass jar with a cork lid."

## Recap

- Split every prompt into a fixed style block and a subject line. Change only the subject.
- Keep style words out of the subject line. Test the block on a few different subjects, then freeze it.
- A vision model can draft the block, but check it, and send clear, large images. Compare every output with an anchor.
