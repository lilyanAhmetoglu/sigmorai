## Goal

After this lesson you can:

- Read a model's inputs and outputs, and say what it can make.
- Split a creative brief into jobs and match each job to an image, video, speech or vision model.
- Choose an edit instead of a new generation when most of an image is already right.

## The problem

A small museum plans a new exhibition. The brief from the marketing lead says:

- A poster with the show title and the dates.
- A short looping video for the screen in the lobby.
- An audio guide, read in two languages.
- Alt text (a short written description) for 50 photos of the artworks, for the website.

The team opens one chat app and types all four jobs into it. The poster never appears. The video never appears. They get only text back. They lose an afternoon.

The problem is not the prompt. The problem is the model. Each job needs a model that **makes** that kind of media.

## The idea

Every model has **inputs** (what it can read) and **outputs** (what it can make). The kinds of media are called **modalities**: text, image, video, audio. The **output modality** is what comes out: the type of media you get back.

Read the output side first. Think of a kitchen: an oven bakes and a blender mixes. You don't ask the blender for bread.

```text
input (reads)            output (makes)
text            ->  [image model]   ->  image
text or image   ->  [video model]   ->  video
text (a script) ->  [speech model]  ->  audio
image + text    ->  [vision model]  ->  text
```

The vendor docs show four kinds of media model:

- **Image models.** The [OpenAI docs](https://developers.openai.com/api/docs/guides/image-generation) list two endpoints. _Generations_ make images "from scratch based on a text prompt". _Edits_ "modify existing images using a new prompt, either partially or entirely". The [Gemini API docs](https://ai.google.dev/gemini-api/docs/image-generation) call Google's image models Nano Banana. You can "mix up to 14 reference images" into one result.
- **Video models.** The [Gemini API docs](https://ai.google.dev/gemini-api/docs/veo) say Veo 3.1 is "a model for generating 8-second videos (720p, 1080p, or 4k) with natively generated audio". You can also give it the first and last frames.
- **Speech models** (text to speech). The [OpenAI docs](https://developers.openai.com/api/docs/guides/text-to-speech) say the speech endpoint can "narrate a written blog post" and make spoken audio in many languages. The [Gemini API docs](https://ai.google.dev/gemini-api/docs/speech-generation) say its speech models "accept text-only inputs and produce audio-only outputs". One request supports "up to 2 speakers".
- **Vision models** (image in, text out). The [Claude docs](https://platform.claude.com/docs/en/models/overview) say: "All current models support text and image input, text output". So Claude can look at a poster and write feedback. But the [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision) are clear: Claude "cannot generate, produce, edit, manipulate, or create images." It reads images. It does not make them.

**Text inside images** needs extra care. The OpenAI docs say their model "can still struggle with precise text placement and clarity". The Gemini API docs say Nano Banana can make "legible, stylized text for infographics, menus, diagrams, and marketing assets". They also give a tip: Gemini "works best if you first generate the text and then ask for an image with the text". Either way, check every word by eye.

## Worked example

### Step 1: the plan before

```text
Tool: one chat model (text + image in, text out)
Prompt: "Make our exhibition poster, a lobby video loop,
an audio guide in English and French, and alt text for
50 artwork photos."
```

What goes wrong:

- The chat model's output is text. It can't make the poster, the video or the audio.
- Only the alt text job fits this model.
- Four different jobs sit in one prompt, so nobody checks each one.

### Step 2: write the output for each job

Start from what you must deliver, not from the tool.

| Job                         | Output you need | Input you give        |
| --------------------------- | --------------- | --------------------- |
| Poster with title and dates | image           | text prompt           |
| Lobby video loop            | video           | text prompt or image  |
| Audio guide, two languages  | audio           | the written script    |
| Alt text for 50 photos      | text            | the photos + a prompt |

### Step 3: match each job to a model type

```text
Poster          -> image model  (generate; edit later)
Lobby loop      -> video model  (short clips, cut together)
Audio guide     -> speech model (one script per language)
Alt text        -> vision model (image in, text out)
```

**The hard case is the poster.** It has words in it: a title and dates. Image models can still get text wrong. So the plan adds a check: read every letter and every date on the result. If one is wrong, fix it with an edit, or set the text in your design tool.

### Step 4: the client asks for a change

The client likes the poster but wants a warmer sky. This is an **edit**, not a new generation. You give the existing image and a new prompt. The rest of the poster stays the same, so you don't start again.

### Step 5: why it is better

- **Every job has a model that makes its output.** No job is sent to a model that can't make it.
- **The inputs are clear.** The speech model gets a finished script. The vision model gets the photos.
- **The risky part has a check.** Text in the image is read by a person.
- **Changes are cheap.** An edit keeps the parts the client already likes.

## Common mistakes

1. **Choosing by brand, not by output.** "We use model X for everything." Fix: write the output of each job first, then pick a model that makes it.
2. **Starting again for a small change.** The client wants one detail changed, and you write a brand-new prompt. Fix: use an edit on the existing image.
3. **Trusting text in an image.** A date or a price comes out wrong. Fix: check every word by eye before you send the file.

## Try it

Not graded. Write your answer down before you read the answer.

A yoga teacher sends you this brief:

```text
1. A 5-minute guided relaxation, as a voice track.
2. A square thumbnail for the video page.
3. Read 20 screenshots of student feedback and
   list the three most common requests.
```

For each job, write the output and the model type.

### Answer

1. **Voice track.** Output: audio. Model: a speech model. Input: the written script.
2. **Thumbnail.** Output: image. Model: an image model. If it has text on it, check the text by eye.
3. **Feedback summary.** Output: text. Model: a vision model, because the input is screenshots (images) and the output is a written list.

## Recap

- Read a model's output first. It tells you what the model can make.
- Most media projects use several models, one per job: image, video, speech and vision.
- A model that reads images may not make them. Claude takes images in and gives text out; it does not draw.
