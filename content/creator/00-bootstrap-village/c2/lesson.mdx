## Why it matters

Text models count **tokens**: small pieces of text. Media models count too. An image, a second of audio or a second of video becomes a number of tokens or units, and you pay for that number. Bigger pictures and longer clips usually cost more. This lesson shows how the vendors count, so the bill does not surprise you.

All numbers below are copied from the vendors' docs, checked on 2026-10-06. They change, so check the page before you plan a budget.

## Media counts as tokens

Google's docs put it simply: "All input to the Gemini API is tokenized, including images, video, and audio." OpenAI's vision guide says images "count as tokens and will be billed accordingly."

So a moodboard of 30 photos is not free context. Each photo adds tokens to the request.

## How an image you send is counted

Each vendor cuts the image into small squares and counts them. The size of the square differs.

| Vendor | How it counts an input image                                                                               |
| ------ | ---------------------------------------------------------------------------------------------------------- |
| Claude | 28×28-pixel patches. Tokens = ⌈width / 28⌉ × ⌈height / 28⌉                                                 |
| OpenAI | 32×32-pixel patches on newer models, then a model multiplier (1.2 for gpt-6-astra)                         |
| Gemini | 258 tokens if both sides are 384 pixels or less; larger images are cut into 768×768 tiles, 258 tokens each |

Worked examples from the docs:

- **Claude:** a 1000×1000 image costs 1,296 tokens.
- **OpenAI:** on gpt-6-astra with `high` detail, a 1024×1024 image is 1,024 patches, billed as 1,229 tokens.

## Big images get shrunk

Vendors set a top size. Above it, the image is made smaller before the model sees it.

Claude's docs give two tiers. On Claude 4.7 and later models, the long edge can be up to 2576 px (max 4,784 tokens). On other models it is 1568 px (max 1,568 tokens). A 3840×2160 (4K) screenshot is shrunk to 2576×1449 on the high-resolution tier.

Shrinking caps the cost, but it has a price. Claude's docs warn that a resized image can make text "less legible". Google's docs say the same trade-off for Gemini's `media_resolution` setting: higher resolution helps the model read fine text, "but increase token usage and latency."

Example: you ask a model to proofread the small print on a packaging mock-up. Send a crop of the small print at a good size. Don't send the full 4K artboard and hope.

## How an image the model makes is counted

Output is counted too. Google's docs list the tokens for each Nano Banana 2.1 output size:

| Output size | Example (1:1) | Tokens |
| ----------- | ------------- | ------ |
| 1K          | 1024×1024     | 1,120  |
| 2K          | 2048×2048     | 1,680  |
| 4K          | 4096×4096     | 2,520  |

The shape does not change the count. A 3:2 image at 1K (1264×848) is also 1,120 tokens. The size step (1K, 2K, 4K) is what matters.

OpenAI also prices image generation per token. Its pricing page lists image output tokens for its GPT Image models, and points you to a calculator in the image generation guide for a cost per image.

## Audio and video count by the second

- **Gemini audio input:** 32 tokens per second, so 1 minute = 1,920 tokens.
- **Gemini video input:** 263 tokens per second (standard processing; other modes vary).

Example: you ask a model to summarize a 3-minute client voice memo. That is 3 × 1,920 = 5,760 audio tokens before you type a word.

## What this means for your work

- **Size is a cost choice.** Send the smallest image that still shows the detail you need.
- **Draft small, finish big.** Make draft images at 1K. Make the final hero at 2K or 4K.
- **Crop, don't just shrink.** When the detail is small text, a crop keeps it readable. Keep the context the question needs (for example, the edge of the label).
- **Count before you run.** Photos × tokens per photo × price per token gives a rough cost. Chapter 5 turns this into a budget.
