Agent Citadel, chapter 3 (The harness), put the Agent SDK in the "library in your app" row. Chapters 1 to 3 here set up skills, hooks and plugins for a person at a keyboard. This chapter runs the same coding agent from a script, with nobody at the screen: a nightly job, a build step, a small tool.

"Headless" means the agent runs once, prints a result and exits, with no chat screen (our plain gloss).

A note on dates: the flags, fields and exit codes below are from each vendor's page in October 2026.

## One command per tool

stdout is where a program prints its result; stderr is a second stream for logs and errors (our plain gloss).

| Tool        | Run once from a script | Where the answer goes                       |
| ----------- | ---------------------- | ------------------------------------------- |
| Claude Code | `claude -p "<task>"`   | stdout                                      |
| Codex       | `codex exec "<task>"`  | final message on stdout, progress on stderr |
| Gemini CLI  | `gemini -p "<task>"`   | stdout                                      |

- **Anthropic:** "Add the `-p` (or `--print`) flag to any `claude` command to run it non-interactively."
- **OpenAI:** "Non-interactive mode lets you run Codex from scripts (for example, continuous integration (CI) jobs) without opening the interactive TUI. You invoke it with `codex exec`." (A TUI is a full-screen app in the terminal; our plain gloss.)
- **Google:** "Headless mode is triggered when the CLI is run in a non-TTY environment or when providing a query with the `-p` (or `--prompt`) flag." (Non-TTY means no live terminal is attached, as in a CI job; our plain gloss.)

All three read piped input. Anthropic: "Non-interactive mode reads stdin". Codex treats "the prompt as the instruction and the piped content as additional context." Gemini CLI "reads the standard input (stdin) as context".

Our example: `cat build.log | claude -p "explain the root cause"` and `cat build.log | codex exec "explain the root cause"` do the same job.

## Get output a script can read

Plain text is fine for a person. A script needs fields.

**Claude Code** uses `--output-format`: `text` (the default), `json` ("structured JSON with result, session ID, and metadata") or `stream-json` ("newline-delimited JSON for real-time streaming"; one JSON object per line, our plain gloss). In `json`, the answer text is in the `result` field. Add `--json-schema` with a JSON Schema (a file that describes the shape the JSON must have; our plain gloss), and "the structured output" is in the `structured_output` field.

**Codex** uses `--json`: "`stdout` becomes a JSON Lines (JSONL) stream" (one JSON object per line; our plain gloss), with events such as `thread.started`, `turn.completed`, `turn.failed` and `error`. For only the last message, `-o <path>` (`--output-last-message`) writes it to a file. For a fixed shape, `--output-schema ./schema.json` asks for "a final response that conforms to a JSON Schema."

**Gemini CLI** uses `--output-format json`: one object with `response` (the answer), `stats` and an optional `error`. A streaming JSON option sends JSONL events such as `tool_use`, `tool_result` and `result`.

Our example: `claude -p "list the TODOs" | jq '.result'` fails, because the default output is text. Add `--output-format json` first.

## Check the exit code

A script must know if the run failed.

- **Claude Code:** "exits with code 0 on success and a non-zero code when the run fails". One catch: "When a failure happens inside the run, such as missing authentication, Claude Code prints the failure as the result on stdout."
- **Gemini CLI** lists its codes: `0` success, `1` "General error or API failure", `42` "Input error (invalid prompt or arguments)", `53` "Turn limit exceeded".
- **Codex:** the page lists no exit codes; with `--json`, watch for `turn.failed` and `error` events.

## Decide what the run may do

Nobody is there to say yes, so set the limits before the run starts. Agent Citadel, chapter 6 (Permissions), explained the rules; here are the script flags.

- **Claude Code:** `--allowedTools "Read,Edit,Bash"` pre-approves tools. Or pass a mode: `--permission-mode dontAsk` "denies every call that would otherwise prompt, which is useful for locked-down CI runs"; `acceptEdits` lets Claude write files without asking. Anthropic warns that a run with no mode set takes a built-in starting mode, "which can be `auto`, so pass the one you want".
- **Codex:** "By default, `codex exec` runs in a read-only sandbox." To allow edits: `--sandbox workspace-write`. Use `--sandbox danger-full-access` "only in a controlled environment (for example, an isolated CI runner or container)." `--full-auto` is kept only as "a deprecated compatibility flag".
- **Codex also checks for git.** "Codex requires commands to run inside a Git repository to prevent destructive changes." `--skip-git-repo-check` turns this off.

Our example: `codex exec "fix the lint errors"` reports a fix, but no file changes. The run was read-only. Add `--sandbox workspace-write`.

## Decide what the run loads

A headless run can pick up settings you did not plan for.

- **Claude Code:** without `--bare`, `claude -p` "loads the same context an interactive session would", including hooks and `CLAUDE.md`. Chapter 2 showed the risk: it runs a project's hooks "even in a folder you've never trusted." `--bare` skips "hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and CLAUDE.md". Anthropic: bare mode "is useful for CI and scripts where you need the same result on every machine", and it is "the recommended mode for scripted and SDK calls". One catch: "In bare mode, Claude Code never reads OAuth credentials or the system keychain." (OAuth credentials are the saved browser login; our plain gloss.) Set `ANTHROPIC_API_KEY` instead.
- **Codex:** `--ignore-user-config` makes a run that "doesn't load `$CODEX_HOME/config.toml`", and `--ignore-rules` skips the user and project execpolicy `.rules` files.
- **Gemini CLI:** in an untrusted folder with Folder Trust on, a headless run "will throw a `FatalUntrustedWorkspaceError` and exit." `--skip-trust` or `GEMINI_CLI_TRUST_WORKSPACE=true` trusts the folder for that session. Only do this for a repo you have checked (our advice).

## Run in steps

A two-step job can keep the same conversation.

- **Claude Code:** `--continue` picks up the most recent conversation. For a named one, read `session_id` from the JSON output, then pass `--resume "$session_id"`.
- **Codex:** `codex exec resume --last "<next step>"`, or `codex exec resume <SESSION_ID>`.

## When a script is not enough: the SDKs

A command line is enough for a build step. For your own app, Anthropic and OpenAI each ship an SDK (software development kit: a library you call from your own code; our plain gloss).

- **Claude Agent SDK** (Python and TypeScript): "the same tools, agent loop, and context management that power Claude Code". The packages give you "structured outputs, tool approval callbacks, and native message objects". From another language, Anthropic says to run the CLI "as a subprocess with the `-p` flag and `--output-format json`." Anthropic's terms: it does not allow third-party developers to offer claude.ai login for agents built on the SDK "Unless previously approved"; use API key login.
- **Codex SDK:** OpenAI lists "Control Codex as part of your CI/CD pipeline" as one use. The TypeScript library (`@openai/codex-sdk`) starts a thread with `codex.startThread()`, runs a prompt with `thread.run(...)`, and resumes with `codex.resumeThread(threadId)`. The Python library (`openai-codex`) takes a sandbox per thread or turn: `Sandbox.read_only`, `Sandbox.workspace_write` or `Sandbox.full_access`.

Rule of thumb (our advice): start with the CLI in a script. Move to an SDK when your own code must react to each step, such as approving a tool call.

## Key points

- Run once from a script: `claude -p`, `codex exec`, `gemini -p`.
- Ask for machine output: `--output-format json` (Claude Code, Gemini CLI), `--json` (Codex). Schemas: `--json-schema` → `structured_output`, `--output-schema`.
- Check the exit code. Claude Code can print an in-run failure as the result.
- Set limits first: `--allowedTools` or `--permission-mode` (Claude Code); `codex exec` starts read-only, add `--sandbox workspace-write` to edit.
- Control what loads: `--bare` (Claude Code, needs `ANTHROPIC_API_KEY`), `--ignore-user-config` (Codex), folder trust (Gemini CLI).
- Continue a run: `--resume` (Claude Code), `codex exec resume` (Codex).
- Need your own app? Use the Claude Agent SDK or the Codex SDK.
