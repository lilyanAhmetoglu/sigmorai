## Goal

After this lesson you can:

- Decide between sending a whole knowledge base and using retrieval (RAG).
- Lay out a long prompt for your model: where the documents go, where the question goes, and how each document is framed.
- Recognise a "many needles" task and split it before accuracy drops.

## The problem

A company builds an onboarding assistant for new staff. The knowledge is 14 internal documents: the handbook, IT setup, travel rules, security rules and more. Together they are about 160,000 tokens.

The team first built RAG with the top 5 chunks. Simple questions work. Questions that need two documents fail. Example: "Can I expense a laptop bag if I work remotely?" needs the travel rules and the remote-work policy. Search often returns only one of them.

The team asks: can we just send all 14 documents every time? And if so, how should the prompt look?

## The idea

The **context window** is everything the model can see in one request. The [Claude docs](https://platform.claude.com/docs/en/build-with-claude/context-windows) call it the model's "working memory": "all the text a language model can reference when generating a response, including the response itself." Everything counts: the system prompt, all messages, tool definitions, documents and the output. The [OpenAI docs](https://developers.openai.com/api/docs/guides/conversation-state) say the same: the limit "includes input, output, and reasoning tokens".

Windows are large now. Many Claude models, such as Claude Opus 5.5 and Claude Sonnet 5.5, "have a 1M-token context window". Others, such as Claude Haiku 4.5, have 200k. GPT-4.1 lists a "1,047,576 context window" ([OpenAI model page](https://developers.openai.com/api/docs/models/gpt-4.1)). The [Gemini docs](https://ai.google.dev/gemini-api/docs/long-context) say many Gemini models have "1 million or more tokens".

But a big window is not a perfect memory:

- **The Claude docs:** "As token count grows, accuracy and recall degrade, a phenomenon known as _context rot_."
- **The OpenAI docs** ([GPT-4.1 guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide)): performance "can degrade as more items are required to be retrieved".
- **The Gemini docs:** with several "needles" to find, "the model does not perform with the same accuracy" as with one.

Think of a desk. A bigger desk holds more papers, but finding ten things on it is harder than finding one.

**When to skip RAG.** The [Anthropic Contextual Retrieval post](https://www.anthropic.com/engineering/contextual-retrieval) gives a simple test: "If your knowledge base is smaller than 200,000 tokens (about 500 pages of material), you can just include the entire knowledge base in the prompt". Prompt caching (chapter 4) makes this cheaper and faster. Bigger collections need retrieval.

**Where things go.** The vendors do not agree, so follow the guide for your model:

```text
Claude, Gemini:  [documents] ............ [question]
GPT-4.1:         [instructions] [documents] [instructions again]
```

- The [Claude prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) puts long documents "near the top of your prompt", above the query. In Anthropic's tests, a query at the end raised quality by "up to 30 percent".
- The Gemini docs: performance is usually better "if you put your query / question at the end of the prompt".
- The GPT-4.1 guide (OpenAI): put instructions "at both the beginning and end of the provided context". If you write them only once, "above the provided context" is the better place.

## Worked example

The assistant runs on Claude Sonnet 5.5. Let's build the long-context version step by step.

### Step 1: the weak version

```text
Answer the employee's question using the documents.
Question: Can I expense a laptop bag if I work remotely?

[handbook text][IT setup text][travel rules text] ... (14 documents, pasted together)
```

What goes wrong:

- The question is at the top, above 160,000 tokens of text.
- The documents run into each other. There is no clear edge between them, and no name to cite.

### Step 2: check the size

160,000 tokens is under Anthropic's 200,000-token line, so the whole set can go in. Check the window too: Claude Sonnet 5.5 has 1M, and the answer also needs room. Before you ship, measure real requests with the token counting API. If the input alone is too big, the Claude API returns a 400 error ("prompt is too long").

### Step 3: frame each document, question last

```text
<documents>
  <document index="1">
    <source>travel-rules-2026.md</source>
    <document_content>
    [full text]
    </document_content>
  </document>
  <document index="2">
    <source>remote-work-policy.md</source>
    <document_content>
    [full text]
    </document_content>
  </document>
  ... 12 more ...
</documents>

First, find quotes from the documents that are relevant to the question.
Put them in <quotes> tags, with the source of each quote.
Then answer the question using only those quotes.

Question: Can I expense a laptop bag if I work remotely?
```

Three changes:

- **Documents first, question last**, as the Claude guide says.
- **Each document in tags** with `<source>` and `<document_content>`, so the model can name the source.
- **Quotes first.** The Claude guide says this "helps Claude focus on the relevant content and ignore the rest of the document."

Add `cache_control` after the documents, so the 160,000 tokens are read from the cache on later questions.

### Step 4: the same task on another model

On GPT-4.1, the instructions go both above and below the documents. For the frame, the GPT-4.1 guide says "XML performed well in our long context testing" while JSON did "particularly poorly". So keep XML-style tags there too.

### Step 5: the hard case, many needles

HR asks the assistant: "List every rule in all 14 documents that has a deadline, with the date."

This is many needles at once. The OpenAI and Gemini docs both warn that accuracy drops when many items must be found. The Gemini docs give a way out: for high accuracy on many pieces of information, you "would likely need to send 100 requests" for 100 items, and context caching keeps that affordable.

So split the task:

```text
request 1:  [cached documents] + "List the deadline rules in document 1 only."
request 2:  [cached documents] + "List the deadline rules in document 2 only."
...
request 14: [cached documents] + "List the deadline rules in document 14 only."
then: merge the 14 lists in code
```

Each request has a narrow job. The documents are the same prefix every time, so they come from the cache.

### Why it is better

- **Nothing to miss.** Every document is in the prompt, so cross-document questions work.
- **The model can find and cite.** Tags give each document an edge and a name, and the question sits after the text.
- **Big jobs are split.** Many-needle tasks become many small one-document tasks.

## Common mistakes

1. **"It fits, so it works."** A 1M window does not mean perfect recall. Fix: keep the prompt to what the task needs, and split many-needle tasks.
2. **One layout for every vendor.** Claude and Gemini want the question last; the GPT-4.1 guide wants instructions at both ends. Fix: check the guide for the model you call.
3. **Forgetting the output.** The answer and any thinking also use the window. Fix: count tokens and leave room for the reply.

## Try it

Not graded. A team sends a 230,000-token wiki to Claude Haiku 4.5. Find two problems with this plan.

```text
model:  Claude Haiku 4.5
prompt: "Summarise our on-call process." + the whole wiki (230,000 tokens)
```

### Answer

1. **It does not fit.** Claude Haiku 4.5 has a 200k-token window, and the wiki alone is 230,000 tokens. The API will reject it with a 400 error. Also, 230,000 is above Anthropic's 200,000-token line for skipping RAG. Fix: use retrieval, or a 1M-token model with only the pages you need.
2. **The question is first.** For Claude, put the long text first and the request at the end.

## Recap

- The window holds everything: instructions, messages, tools, documents and the output. A big window still loses accuracy as it fills (context rot).
- Under about 200,000 tokens, Anthropic says you may send every document each time and drop RAG. Prompt caching keeps it cheap.
- Lay out for your model (Claude and Gemini: question last; GPT-4.1: instructions at both ends), frame each document with its source, and split many-needle tasks.
