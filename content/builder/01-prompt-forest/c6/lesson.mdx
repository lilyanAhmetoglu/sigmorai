Models can state false things with full confidence. The Claude docs define this "hallucination" as text that is "factually incorrect or inconsistent with the given context". A grounded answer is one that comes from text you supplied, not from the model's memory or guesses. This chapter gives four tools: allow "I don't know", restrict the sources, quote before answering, and verify after answering.

## 1. Allow "I don't know"

If the prompt says "answer every question", the model will answer every question, even when your documents have no answer.

The Claude docs: "Explicitly give Claude permission to admit uncertainty. This simple technique can drastically reduce false information." Their example tells the model to say "I don't have enough information to confidently assess this" when the report lacks the information.

Gemini's grounding clause ends the same way: "If the exact answer is not explicitly written in the context, you must state that the information is not available."

Example: an HR assistant gets "What is parental leave for contractors?" The handbook covers employees only. A grounded system replies "The handbook does not cover contractors" and does not invent a number.

Give the exact fallback sentence. Then your app can detect it and, for example, offer to contact HR.

## 2. Restrict the answer to the given text

Tell the model which text it may use.

- Claude: "Explicitly instruct Claude to only use information from provided documents and not its general knowledge."
- Gemini's example prompt: "Answer the question using the text below. Respond with only the text provided."
- OpenAI's citation rules for injected context include "Never cite outside knowledge or outside authorities."

More context is not always safer. OpenAI's accuracy guide warns that "you can supply too much irrelevant context, which drowns out the real information and causes hallucinations." Send the relevant parts. Realm 3 covers retrieval in depth.

## 3. Quote first, then answer

For long documents, ask the model to pull the exact supporting text before it answers.

The Claude docs: "For tasks involving long documents (>20k tokens), ask Claude to extract word-for-word quotes first before performing its task." Their example also gives a fallback: "If you can't find relevant quotes, state 'No relevant quotes found.'"

```text
<handbook>
...
</handbook>

1. Find quotes from the handbook that answer the question.
   Put them in quotes tags. If there are none, write "No relevant quotes found."
2. Answer using only those quotes. Refer to each quote by its number.
```

Example: asked about leave carry-over, the model first quotes section 4.2. The answer then rests on that quote, and a reviewer can check it in seconds.

## 4. Verify the answer against the text

After the answer, check each claim.

- The Claude docs suggest having the model "verify each claim by finding a supporting quote after it generates a response. If it can't find a quote, it must retract the claim."
- OpenAI's citation guide describes a full system: "you decide what can be cited, represent that material clearly, instruct the model how to cite it, and validate the result before it renders to the user."

OpenAI's rules for injected context, to put in your prompt:

- "Cite only blocks that appear in the provided context."
- "Never invent new block IDs."
- "If the provided blocks conflict, cite the conflicting blocks and describe the conflict accurately."

Give each block a stable ID (chapter 3 showed how to label documents). Then your code can check that every cited ID really exists before the answer is shown.

Example: the answer cites `block7`, but the prompt only had `block1` to `block5`. Your code blocks the answer and retries, or shows "could not verify".

## Built-in citation features

You can also let the API produce the citations.

- **Claude** has a citations feature for documents. The docs say the citations "are guaranteed to contain valid pointers to the provided documents", and the quoted `cited_text` "does not count toward your output tokens". One limit: citations "cannot be used together with structured outputs"; a request with both returns a 400 error.
- **OpenAI** notes that its hosted tools, such as web search, "provide automatic inline citations".

Example: a policy assistant on Claude turns on citations for the handbook document. Cited parts of the answer arrive with the exact passage they came from, and the UI shows it on hover.

## Not zero

The Claude docs end with a clear warning: these techniques "significantly reduce hallucinations", but "they don't eliminate them entirely. Always validate critical information, especially for high-stakes decisions."

Example: a grounded HR assistant can answer routine questions directly. An answer about pay or legal rights still links to the source section and invites the employee to confirm with HR.

## Key points

- Give the model an explicit way out ("I don't know", "not available") and a fixed sentence for it.
- Restrict answers to the supplied text. Send relevant context, not everything.
- Long documents: extract word-for-word quotes first, then answer from them.
- Verify: every claim needs a supporting quote; every citation must point to a real, supplied block. Check it in code.
- Claude's citations feature guarantees valid pointers but cannot be combined with structured outputs.
- Grounding reduces hallucinations; it does not remove them. Validate high-stakes answers.
