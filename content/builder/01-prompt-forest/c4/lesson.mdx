Some tasks need steps: compare a policy with an order, plan a migration, debug a failing check. "Chain of thought" means the model works through the steps before it gives the answer. There are two ways to get it: a built-in reasoning mode, or a prompt that asks for it. Today the built-in mode is the main one, so start there.

## Built-in reasoning

Current models from all three vendors can reason internally before they answer.

- OpenAI: reasoning models "use internal reasoning tokens before producing a response", which helps them "plan, use tools effectively, inspect alternatives, recover from ambiguity, and solve harder multi-step tasks".
- Gemini: models "use a 'thinking process' that significantly improves their reasoning and multi-step planning abilities".
- Claude: thinking is adaptive: "the model evaluates each request and decides for itself whether to think and how much."

You control it with a setting, not with a sentence in the prompt.

## The setting differs by vendor

- **Claude**: an effort level at `output_config.effort`. The levels run from `low` ("Skips thinking for simple tasks where speed matters most") to `max`. Which levels a model supports varies by model. Check the effort page before you choose.
- **OpenAI**: `reasoning.effort`. Values are "model-dependent and can include `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max`".
- **Gemini**: `thinking_level`, for example `low`, `medium` or `high`, depending on the model.

Defaults differ by model too. Read the model's page before you choose; do not assume.

## Don't ask a reasoning model to "think step by step"

Old prompts often say "think step by step". With built-in reasoning, that line is usually not needed.

- OpenAI's reasoning guide: "Avoid chain-of-thought prompts". It also says that "think step by step" may not enhance performance "(and can sometimes hinder it)".
- Gemini: "it's generally not necessary to have the model outline, plan, or detail reasoning steps in the returned response itself." For very hard problems, a short request like "Think very hard before answering" can help, "though at the cost of extra thinking tokens".
- Claude: "Prefer general instructions over prescriptive steps. A prompt like 'think thoroughly' often produces better reasoning than a hand-written step-by-step plan." On the current Claude models named in the prompting guide (Fable 5.1, Fable 5, Opus 5.5, Opus 5, Sonnet 5.5), a prompt that asks the model to write its reasoning out in the reply "may be declined"; the docs say to rely on thinking instead.

Example: a prompt says "Think step by step and write your full reasoning, then the answer." On a reasoning model, delete the first half. Keep a precise goal and success criteria (chapter 1).

## Manual chain of thought, as a fallback

When thinking is off, the Claude docs still allow the classic method: ask the model "to think through the problem before it answers, and to put the final answer in `<answer>` tags so you can extract it".

```text
Check whether this order can be refunded under the policy.
Work through the policy conditions first.
Then give only "eligible" or "not eligible" inside answer tags.
```

Your code reads only the text inside the answer tags. Use this for models or modes without built-in thinking.

## Ask for a self-check

The Claude docs suggest adding a line like "Before you finish, verify your answer against [test criteria]." They say this "catches errors reliably, especially for coding and math". One caution from the same page: on Claude Opus 5, such lines can cause over-verification, so remove them there.

Example: "Before you finish, check that every refund decision cites a policy clause."

## Reasoning costs tokens

Reasoning is not free. It is billed even when you do not see it.

- OpenAI: reasoning tokens "are not visible via the API", but "still occupy space in the model's context window and are billed as output tokens".
- Claude: thinking tokens are "billed as output tokens", and "You are billed for the full thinking process, not the thinking content visible in the response."
- Gemini: "response pricing is the sum of output tokens and thinking tokens."

Example: the visible answer is 200 tokens, but the model used 3,000 reasoning tokens. You pay for 3,200 output tokens.

## Leave room in the output cap

The output cap includes the reasoning:

- Claude: `max_tokens` "is a hard cap on total output for the request, thinking and response text combined".
- OpenAI: when the cap is reached you get `status` `incomplete` with reason `max_output_tokens`. "This might occur before any visible output tokens are produced, meaning you could incur costs for input and reasoning tokens without receiving a visible response." OpenAI recommends "reserving at least 25,000 tokens for reasoning and outputs when you start experimenting".
- Gemini: `max_output_tokens` includes thought tokens. To cut cost without cutting answers, lower `thinking_level` "instead of setting a small `max_output_tokens`".

So a tiny cap is the wrong tool for saving money. Lower the effort instead, and size the cap for reasoning plus answer.

## Match effort to the task

OpenAI's effort guide gives use cases: `none` for things like "voice, fast information retrieval, and classification"; `low` for work such as "customer support / chat assistant workflows"; `high` for "hard reasoning, complex debugging, deep planning". For `xhigh`: "Only use when your evals show a clear benefit that justifies the extra latency and cost."

The Claude docs agree on method: "measure before you ship". Compare quality, output tokens and latency with and without the change.

Example: a router sends simple FAQ questions to low effort and multi-step refund disputes to high effort. One test set checks both paths.

## Key points

- Built-in reasoning is a setting: Claude `output_config.effort`, OpenAI `reasoning.effort`, Gemini `thinking_level`.
- With built-in reasoning, drop "think step by step". Give a clear goal instead.
- Manual chain of thought (reason, then answer in tags) is a fallback when thinking is off.
- Reasoning tokens are billed as output, even when hidden.
- The output cap includes reasoning. Lower effort to save cost; don't shrink the cap.
- Pick effort per task and measure the difference.
