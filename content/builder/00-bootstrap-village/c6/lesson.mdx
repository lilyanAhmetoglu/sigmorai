## Goal

After this lesson you can:

- Estimate a feature's monthly model cost from token counts and a price list.
- Find the hidden tokens that make a bill bigger than the plan.
- Pick the right lever to cut cost: model size, prompt caching, batch, output caps and spend limits.

## The problem

An online shop wants a model to write product descriptions. Every day about 5,000 new products arrive. Each request sends a 2,500-token style guide plus about 500 tokens of product data, and gets back a description of about 400 tokens. The descriptions must be ready by the next morning.

Finance asks two questions: "What will this cost per month?" and "How can we make it cheaper?" The team also wants to test a reasoning model, because it writes better descriptions.

This lesson answers both questions.

## The idea

**Cost is tokens times price.** Both vendors price per million tokens (MTok), with one price for input and another for output. The [OpenAI pricing page](https://developers.openai.com/api/docs/pricing) says: "Prices per 1M tokens." The [Claude pricing page](https://platform.claude.com/docs/en/about-claude/pricing) lists prices as "/ MTok".

```text
cost = input tokens  / 1,000,000 × input price per MTok
     + output tokens / 1,000,000 × output price per MTok
```

On the Claude price list, output costs more per token than input for each model. So reply length moves the bill a lot. This lesson uses **made-up example prices**. Real prices change, so read the live pricing page before you plan a budget.

**Hidden tokens.** The estimate is only as good as the token counts. Teams often forget:

- **History.** Each turn resends the chat (chapter 2). With OpenAI's `previous_response_id`, earlier input tokens in the chain "are billed as input tokens in the API" ([conversation state](https://developers.openai.com/api/docs/guides/conversation-state)).
- **Tools.** With `tools`, the Claude pricing page says "the API also automatically includes a special system prompt for the model that enables tool use".
- **Images and PDF pages** (chapter 4).
- **Thinking and reasoning.** The [Claude docs](https://platform.claude.com/docs/en/build-with-claude/context-windows) say thinking tokens "are billed as output tokens". The [OpenAI reasoning guide](https://developers.openai.com/api/docs/guides/reasoning) says reasoning tokens "are not visible via the API" and are billed as output. A short visible answer can carry many paid output tokens.

**Lever 1: a smaller model.** The Claude pricing page advises: "Choose Haiku for simple tasks, Sonnet for most production workloads, and Opus for the most complex reasoning". Test the smallest model that passes your checks (chapter 5).

**Lever 2: prompt caching.** Many requests start with the same long text. Caching reuses that start, the **prefix**, at a lower price. Think of it as a shop that keeps your usual order ready: it is faster and cheaper, but only if you order the same thing first.

- Claude: a cache read costs "0.1x base input price" on most models ("All other models use the standard 0.1x multiplier"). A cache write costs more: "1.25x base input price" for 5 minutes, "2x base input price" for 1 hour. The pricing page says caching "pays off after one cache read" for the 5-minute cache.
- OpenAI: "Prompt caching is enabled by default for supported OpenAI models." The [caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) says "Cache reuse requires the entire rendered prefix to match", and advises: "Put stable developer instructions and shared reference material first."

The rule for both: **the same text first, the changing text last.**

```text
good: [style guide (same every time)][product data (changes)]
bad:  [product data (changes)][style guide (same every time)]
       ^ the start changes on every call, so nothing is reused
```

**Lever 3: batch what can wait.** Work with no user waiting can run as a batch.

- Claude: the Batch API gives "a 50% discount on both input and output tokens".
- OpenAI: the [Batch API](https://developers.openai.com/api/docs/guides/batch) gives a "50% cost discount compared to synchronous APIs". "Each batch completes within 24 hours (and often more quickly)", and batch jobs use "a separate pool of significantly higher rate limits".

The Claude pricing page says: "Batch API and prompt caching discounts can be combined."

**Lever 4: cap and measure.**

- **Cap output** with `max_tokens` or `max_output_tokens`, sized for the task.
- **Log `usage`** from every response, per feature. It is the real bill, not the plan.
- **Set spend limits.** Claude organizations have a monthly spend cap per tier. The [Claude docs](https://platform.claude.com/docs/en/api/rate-limits) say: "Once you reach your tier's spend cap, API usage pauses". OpenAI suggests setting spend limits "for your organization or projects to control monthly API spend" ([rate limits](https://developers.openai.com/api/docs/guides/rate-limits)). Alert before you reach a limit.

## Worked example

Example prices (made up, not a real price list): input **$1 per MTok**, output **$8 per MTok**.

### Step 1: the first estimate

```text
per request:  3,000 input (2,500 guide + 500 product), 400 output
per day:      5,000 requests

input:   5,000 × 3,000 = 15,000,000 = 15 MTok × $1 = $15
output:  5,000 ×   400 =  2,000,000 =  2 MTok × $8 = $16
day:     $31            30-day month: $930
```

Output is only about 12% of the tokens, but more than half of the cost.

### Step 2: put the style guide first

The template puts the 2,500-token style guide at the start and the product data at the end. Now the start of every request is the same, so caching can reuse it. On most Claude models, at 0.1× for cache reads, the 2,500 guide tokens cost like 250 normal tokens on each read. The 500 product tokens stay at full price.

### Step 3: run it as a batch

Nobody waits for each description; they are needed by the next morning. The job runs once a night through the Batch API, with "a 50% discount on both input and output tokens" on Claude and a 50% discount on OpenAI. Batch alone takes the month from **$930 to $465**, and caching cuts the input part further.

### Step 4: test the reasoning model with `usage`

The test shows `usage.output_tokens` of about 2,000 for a 120-word description. The visible text is short, but hidden reasoning is billed as output.

```text
output per day: 5,000 × 2,000 = 10 MTok × $8 = $80   (was $16)
```

**This is the hard case.** The better text costs five times more output. The team must decide if the quality is worth it, or try a lower reasoning setting or a smaller model on the same tests.

### Why it is better

- **Real numbers.** The estimate uses tokens and the price list, then `usage` checks it.
- **The right levers.** Batch fits work that can wait; caching fits a long, fixed start.
- **No surprises.** Hidden reasoning tokens are measured before the switch, not found on the invoice.

## Common mistakes

1. **Pricing output at the input rate.** Output usually costs more per token. Fix: multiply input and output by their own prices, then add.
2. **Putting the changing text first.** Then the prefix never matches and caching does nothing. Fix: fixed text first, changing text last.
3. **Using live calls for work that can wait.** You pay full price and use your live limits. Fix: send overnight and bulk jobs through a Batch API, as long as its time window fits your deadline.

## Try it

Not graded. Write your answer down before you read the answer.

A review-tagging job uses made-up prices: input $0.50 per MTok, output $4 per MTok. It runs 10,000 requests a day. Each request uses 1,200 input tokens and 300 output tokens.

1. What does it cost per day, and per 30-day month?
2. The tags are needed within two days. Which lever fits best, and what is the new monthly cost?
3. Every request starts with the review text and ends with the same 1,000-token tag list. What should change?

### Answer

1. Input: 10,000 × 1,200 = 12 MTok × $0.50 = $6. Output: 10,000 × 300 = 3 MTok × $4 = $12. **$18 a day, $540 a month.**
2. **Batch.** The deadline is longer than a 24-hour batch window, and batch is 50% off: about **$270 a month**.
3. **Move the fixed tag list to the start** and the review text to the end. Then the cache can reuse the same start on every call.

## Recap

- Cost = input tokens × input price + output tokens × output price, per million tokens. Use made-up prices to practise; read the live page for real budgets.
- Hidden tokens add up: history, tools, images, and reasoning (billed as output, even when you cannot see it).
- Levers: a smaller model, prompt caching (fixed text first), batch for work that can wait (50% off), output caps, spend limits, and `usage` on every call.
