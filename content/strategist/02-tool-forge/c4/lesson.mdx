## Why it matters

You have a scored use case. The next question is how much to build yourself. Building too much wastes months. Building too little can leave you stuck with a tool that can't reach your data or follow your process.

"Build or buy" sounds like two choices. In practice it is a scale: how much of the work you do, and how much you hand to a vendor.

## The scale, in the vendors' own words

Anthropic's use case guides describe three paths that differ in how much control you keep and how much you hand over:

- **Messages API**: the most control. You write the agent loop and run your own tools and infrastructure.
- **Claude Agent SDK**: in between. It provides the agent loop and tool execution, in a process you operate.
- **Claude Managed Agents**: you hand over the most. Anthropic hosts the agent loop, tool execution and runtime.

OpenAI's agents guide offers a similar set and rates the integration effort for each:

- **Agents API**: OpenAI manages the agent and saves its progress. Effort: low.
- **Agents SDK**: runs inside your application, with your own tools and workflows. Effort: medium.
- **Responses API**: you call models directly or build an agent from scratch. Effort: high.

The same page points to **ChatKit** if you want to add an embedded chat experience.

At the far "buy" end sit ready-made products. OpenAI's cookbook shows ChatGPT **workspace agents**, built through a conversational builder inside ChatGPT. It says they are in research preview for ChatGPT Business, Enterprise and Edu customers, and that you can start from pre-built templates such as a Chief of Staff, Data Analysis or Customer Support agent.

## What you trade

Moving toward "buy" means less integration effort, as OpenAI's ratings show. Moving toward "build" means more control over steps, data and connections to your systems, as Anthropic's paths show.

OpenAI's comparison table shows where that control lives. For the managed option, OpenAI runs the agent harness. For the SDK, the agent runs inside your application, and state between tasks is kept in your storage and SDK sessions. The difference matters when your auditors ask where the data is and who runs the code.

Example: a sales team wants a brief before each customer meeting. The cookbook builds exactly this as a workspace agent: it reads calendars, searches documents and the web, and writes a brief each day. If that covers your mapped steps, buying is the fast choice. If the brief must also pull scores from your own pricing system and write them back, you may need more control.

## Four questions to ask

1. **Does the product cover your mapped steps?** Check each step from chapter 1 against what the product really does, not the demo.
2. **Who can see which data?** The cookbook shows that a connected app can use each user's own account or one shared account. With the shared account, anyone the agent is shared with can access those files. Admins can also limit what an agent may do with a connected app, for example read actions but no write actions.
3. **What must be switched on?** The cookbook lists admin steps first: agents enabled for the workspace, permission to build and share, and the needed apps enabled. A "ready-made" product still needs owners.
4. **Who maintains it?** Someone must update instructions, check results and handle changes, on any path.

## Build only as much as you need

Anthropic's "Building effective agents" post recommends finding the simplest solution possible, and adding complexity only when needed.

It also warns about frameworks. They make it easy to start, but they can add layers that hide the underlying prompts and responses, which makes problems harder to debug. They can also tempt teams to add complexity when a simpler setup would do. The post suggests developers start with the model APIs directly, and says incorrect assumptions about what a framework does are a common source of errors.

For a strategist, the lesson is simple: ask the team to explain what the tool does under the hood. If nobody can, that is a risk.

## Expect the options to change

These products move fast. OpenAI's workspace agents are a research preview. Anthropic's "Building effective agents" post now carries a note that much of the tooling it describes has changed since December 2024.

So keep the parts that don't depend on a vendor in your own hands: your workflow map, your success criteria and your test examples. With those, you can compare a new option, or switch, without starting again.

## Key points

- Build vs buy is a scale: how much you control versus how much the vendor runs.
- Both Anthropic and OpenAI offer a direct API, an SDK and a vendor-hosted option.
- Ready-made products start fast but need admin setup and data-access checks.
- Build only as much as you need; frameworks can hide what really happens.
- Keep your map, criteria and test examples, so you can switch when options change.
