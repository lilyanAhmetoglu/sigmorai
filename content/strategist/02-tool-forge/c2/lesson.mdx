## Why it matters

Your workflow map from the last chapter has many steps. Which ones should you look at first? Start with the ones that repeat.

A task done 2,000 times a month is usually a better first target than a hard task done twice a year. Each minute you save is multiplied by the volume. And a repeated task gives you many real examples to test with.

## What the vendor guides point to

Anthropic's customer support guide lists signs that an LLM fits support work. The first sign is a **high volume of repetitive queries**. The guide says Claude can handle many similar questions efficiently, which frees human agents for more complex issues. Other signs on its list: a need for 24/7 support, sudden peaks in volume, and a consistent brand voice.

Anthropic's legal summarization guide starts the same way: you want to review a **high volume of documents** efficiently. It also lists two more repeatable jobs: pulling out key data, such as parties, dates and clauses, and writing summaries in a standard format.

OpenAI's cookbook on ChatGPT workspace agents describes the same pattern from a sales team. It says sales teams often spend time manually pulling account notes, customer feedback, usage metrics and company news before customer meetings. Its example agent runs each day, checks tomorrow's meetings and writes a brief for each one.

## Four signs of good repetition

Look for steps on your map that show all four:

1. **Same task, many times.** Count it. "About 400 invoices a week" is a fact; "lots of invoices" is not.
2. **Same kind of input.** Every invoice has a supplier, a date and a total. Every meeting has a customer name and attendees.
3. **Same shape of output.** A label, a filled form, a summary in a fixed template.
4. **Rules you can write down.** "Refunds under 50 euros are approved" can be tested. "Maria just knows" can't.

Example: an insurance broker's team writes about 1,200 renewal reminder letters a month. Each uses the same customer fields and the same template, and the rules for each policy type are written down. That passes all four signs.

Compare: the same team also writes a custom report for the board twice a year. It is hard, slow work, but it is rare and different every time. It is a poor first target.

## Repetition that can wait costs less

Some repeated work needs an answer now, like a live chat. Other work can wait an hour or overnight, like rewriting product descriptions. Both vendors give a lower price for the second kind.

- Anthropic's batch processing page says its Message Batches API cuts costs by 50%. It suits large volumes that don't need an immediate answer, and most batches finish in less than 1 hour. Its examples include content moderation, data analysis and bulk content generation, such as product descriptions.
- OpenAI's Batch API page also says 50% lower costs, with a 24-hour turnaround. It names jobs like classifying large datasets and running evaluations.

Example: an online shop wants new descriptions for 8,000 products. Nobody is waiting for each one, so it can run as one batch job.

When you list repeated tasks, add one column: "Does someone wait for the result?"

## Volume multiplies cost, too

Repetition multiplies savings, and it multiplies spend. OpenAI's model selection page asks: how often does your workflow run? It says a frequent automation makes usage and cost add up faster than an occasional project. Its advice: compare models on the same inputs and keep the lightest setting that meets your quality bar.

Anthropic's model guide gives a similar option. It says starting with a faster, cheaper model is often enough, and lists high-volume, straightforward tasks among the best fits for that approach.

So a high-volume task is a good candidate, and also the one where model choice matters most for cost.

## Common traps

- **Frequent but tiny.** A 20-second task done 50 times a week saves less than 20 minutes. Do the multiplication.
- **Repetitive but risky.** The legal guide says Claude can be prompted to add citations, so legal staff can review and verify the summary. Volume doesn't remove the need for review.
- **Repetitive but already solved.** If a simple rule or existing tool already does the step well, it is not an AI opportunity.

## Key points

- Repetition is the first filter: count how often each step happens.
- Good repetition has the same task, same input, same output shape and written rules.
- Rare, one-off work is a poor first target, even if it is hard.
- Work that can wait suits batch processing, which both vendors price 50% lower.
- High volume multiplies cost too, so test lighter models on high-volume tasks.
