## Why it matters

Your chief financial officer will ask one thing: "What do we get for the money?" ROI (return on investment) is the usual answer. A good ROI model for AI is not a vendor's slide with one big number. It counts every gain, every cost and every kind of mistake.

The ROI formula itself is plain arithmetic, and it is ours, not a vendor's:

**ROI = (benefit − total cost) ÷ total cost**

Example: a tool saves $50,000 a year and has a total cost of $20,000. Net benefit is $30,000. ROI is 30,000 ÷ 20,000 = 150%.

The hard part is not the formula. It is getting honest numbers for "benefit" and "total cost".

## Start with what a result is worth

OpenAI's accuracy guide gives a method for the business side. First, list the main success and failure cases and give each an estimated cost. The guide says this gives a clear picture of what the solution is likely to save or cost, based on pilot performance.

Its customer service example uses these values:

- AI solves a case that a human solved before: saves **$20**.
- AI escalates a case to a human when it should not: costs **$40**.
- In the worst case, a customer is so frustrated that they leave: costs **$1,000**. The guide assumes this happens in 5% of cases; its table works out to 5% of the failures.

For 1,000 cases, the guide's table shows 815 successes (+$16,300), 175.75 escalations (−$7,030) and 9.25 lost customers (−$9,250). The result is +$20 on 1,000 cases, which is about zero. So 815 successes in 1,000 is the break-even point: **81.5%**.

Break-even accuracy is the accuracy where the pilot neither gains nor loses money. Below it, the AI costs more than it saves.

You can check the guide's number. A failure costs on average 0.95 × $40 + 0.05 × $1,000 = $88. Break-even is where 20 × accuracy = 88 × (1 − accuracy). That gives 81.5%.

The guide draws two conclusions from its pilots:

1. Even if the AI escalated to humans more often than wanted, it still saved a lot. So an accuracy of 85% could be fine, if most of the failures were early escalations.
2. Where a failure is very costly, such as a fraud case resolved wrongly, a human should drive and the AI should assist.

The lesson: it is not only how often the AI is wrong. It is what each kind of wrong costs.

## Count the benefit carefully

These points are ours, not from a vendor page:

- **Time saved is not cash saved.** If 10 people each save 30 minutes a day, no money leaves the budget. Count it as a benefit only if the time is used for paid work, or the team avoids a hire.
- **Use the loaded hourly cost.** That is salary plus the other costs of employing someone.
- **Count only what is used.** If 40% of staff use the tool, the benefit is not 100% of the staff's time.
- **Use measured numbers.** Take time saved from your pilot (chapter 5), not from a brochure.

## Count every cost

Usage fees are only one line. Add these, and label each as measured or estimated:

- Licences and usage fees.
- Set-up and integration work.
- **Review time.** People who check or fix the AI's work. This is the line that vendor slides leave out.
- The cost of mistakes that slip through.
- Training and ongoing upkeep of your tests (chapter 2).

## Compare cost per finished task

Anthropic's cost guide says price lists are written per token, but you pay for completed tasks. So compare models on **cost per completed task**, not cost per token. Its example: a model with a higher price per token can finish a task with fewer turns and less backtracking. The guide also says the ranking flips by workload, and no price list tells you which way. Price every candidate on your own traffic.

OpenAI's model selection page gives the same advice in other words: experiment with the same inputs and keep the lightest setting that meets your quality bar. It lists questions to ask. How often does the workflow run? How quickly do you need the result? How important is quality?

So the question for a cheaper model is not "is it cheaper?" It is "does it still meet the quality bar, and what is the cost per correct result?"

## Cheap ways to cut cost

Both vendors list ways to lower the bill:

- OpenAI's cost guide lists three strategies: reduce the number of requests, minimise tokens, and select a smaller model that keeps accuracy. It also names its Batch API and flex processing as ways to lower cost.
- Anthropic's cost guide says batch processing takes 50% off in exchange for results arriving within 24 hours. Use it for work nobody is waiting on.

Anthropic also says its results are directional and not guarantees, and tells you to measure on your own workload.

## Show a range, not one number

Build three versions: a cautious case, a base case and a good case. Change one input at a time and see which one moves the result most. This is our method.

Example: a pilot saves $4,000 a month and costs $3,000. If review time doubles, the net benefit can turn negative. That tells the team where to look first: the review step, not the licence fee.

## An ROI sheet

This sheet is a tool for this course:

| Line              | Value | Measured or estimated |
| ----------------- | ----- | --------------------- |
| Time saved (paid) |       |                       |
| Fewer errors      |       |                       |
| Licence and usage |       |                       |
| Review time       |       |                       |
| Cost of misses    |       |                       |
| One-off set-up    |       |                       |
| Net per month     |       |                       |
| Payback in months |       |                       |

Payback in months = one-off cost ÷ net benefit per month.

## Key points

- ROI = (benefit − total cost) ÷ total cost. Count every cost, including review time.
- Give each success and failure a cost, then find the break-even accuracy.
- Compare models on cost per completed task, not cost per token.
- Keep the lightest setting that meets your quality bar.
- Show a range, and find which input moves the answer most.
