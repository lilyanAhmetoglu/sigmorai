What prompt caching does

Most requests to a model repeat the same opening: a long system prompt, tool definitions, a reference document. Prompt caching stores the processed form of that prefix, so the next request that starts the same way skips the work. You pay less for those tokens and the first token arrives sooner.

The cache is keyed on an exact prefix match. Change one character early in the prompt and everything after it is a cache miss.

Marking a cache breakpoint

Put stable content first and mark the end of it. Everything up to the breakpoint becomes cacheable. 

{
  "system": [{
    "type": "text",
    "text": "<400 lines of product docs>",
    "cache_control": { "type": "ephemeral" }
  }],
  "messages": [{ "role": "user", "content": "How do refunds work?" }]
}
MENTOR NOTE Put the user's question last. Anything that changes per request belongs after the breakpoint.

When it pays off

  • Chat assistants with a long, fixed system prompt
  • Agents that resend the same tool definitions every turn
  • Q&A over one large document
