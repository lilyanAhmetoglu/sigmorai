SMITH KORREN

A tool is a promise. Describe it truthfully, and the Oracle will reach for it at the right moment. Describe it badly, and the fog fills the gap.

Models don’t run code. When you give one a tool, you’re giving it a name, a description and an input schema. If the model decides the tool helps, it replies with a request to call it — your code runs the function and sends the result back.

The schema is plain JSON Schema. Mark the fields the model must always fill as required, or it may leave them out.

tools = [{
  "name": "get_stock_price",
  "description": "Latest price for a ticker symbol.",
  "input_schema": {
    "type": "object",
    "properties": { "ticker": { "type": "string" } },
    "required": ["ticker"]
  }
}]

OpenAI calls the same idea function calling and names the field parameters. The shape is the same.

SMITH KORREN

Not every ore is worth the fire. A good strategist picks the work where the Oracle is strong and a mistake is cheap.

A good first AI use case has three things: high volume (the work repeats often), clear success criteria (you can tell a good output from a bad one), and a low cost of error (a person reviews the output, or a mistake is easy to undo).

VOLUMEHow often does it happen?
CLARITYCan you judge the output?
RISKWhat does a mistake cost?

Start with work that scores well on all three. Save high-risk, low-volume decisions for later, once you have evals and review steps in place.
